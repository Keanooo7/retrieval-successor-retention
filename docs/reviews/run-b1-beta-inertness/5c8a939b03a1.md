## Findings

No BLOCKER. No MAJOR.

### m1 — MINOR: a non-finite loss or φ crashes (exit 1) instead of being VOID (exit 3) as PREREG §8 requires

- **Where:** `run.py:370-373` and `:390-391` raise `FloatingPointError`. Only `ControlFailure` is
  caught (`run.py:618`), so a NaN produces a traceback, exit 1 and **no ledger**. PREREG §8 lists
  "any loss or φ entry is non-finite" under VOID (exit 3).
- **Also:** φ is checked for finiteness only at the 4 snapshots, not at every step. A transient
  non-finite φ is caught at the next snapshot, and the loss is checked at every step.
- **Did not fire in this run** (rc 0).
- **Fix:** raise `ControlFailure` (or catch `FloatingPointError` alongside it) so that the ledger
  records `did_not_run` with the reason.

### m2 — MINOR: the VOID and verdict wiring in `aggregate`/`run_all` is untested

- **Untested code:**
  - the N check (`run.py:529-537`);
  - the P-must-be-LIVE check (`:538-540`);
  - the T0-at-end check (`:626-627`);
  - the rc and outcome mapping (`:663-680`).
- **Consequences:**
  - A mutation such as `if not n_ok:` → `if False:` would survive the test file and the battery.
  - `test_train_one_...` checks N's determinism at the `train_one` level, not that `aggregate`
    acts on it.
- **Mitigation:** the verifier independently confirmed N bit-identical, P LIVE and `void == []`
  for this run. The risk is to a re-run, not to these numbers.
- **Fix:** add a test that feeds `aggregate` a hand-built `runs` dict in which N differs by one
  ulp, or P is INERT, and asserts `void` is non-empty and `run_all` returns 3. Add the matching
  mutations.

### m3 — MINOR: B1's reproducibility depends on B2's `run.py` staying frozen

- **Where:** `run.py:55`, `_load("_b1_b2", "experiments/b2-psi-probe/run.py")`.
- **Risk:** `PREREG_COMMIT` pins the PREREG, not the B2 code. B2 has had post-run fix commits
  before (P0.2, F1-F10).
- **Fix:** record B2 `run.py`'s blob sha in the manifest, or note in RESULTS that a re-run must
  check out 412f136.

### m4 — MINOR (documentation): off-by-one in the g_T step mapping

- **Where:** `run.py:376` uses `g_T[k % 1000]` with 0-based `k`, so B1 step 1 reads arm B step
  2000.
- **PREREG wording:** §4 says "step `2000 + (k mod 1000)` at B1 step `k`", and the code elsewhere
  numbers B1 steps from 1 (`step = k + 1`). Under that reading, step 1 should read 2001.
- **Effect:** immaterial, since it only shifts which logged norm pairs with which step. It should
  be stated rather than left ambiguous.
- **Fix:** add a one-line note in RESULTS or the docstring.

### m5 — MINOR (reading, not code): decoupled_wd and phi_clip at ε = 1e-8 are LIVE by the rel criterion alone

- **Per-cell values** (seeds 0, 1, 2; the verifier's values):
  - rel at β = 0.01 is 0.131, 0.176 and 0.141;
  - agreement is 0.971, 0.979 and 0.978, which alone would give INTERMEDIATE.
- **Scale from the I control:** a different φ init gives rel 0.159-0.168 at agreement 0.996-0.998.
  The rel criterion therefore partly measures drift in weakly constrained directions of φ, not
  only a change in function.
- **Why no change is needed:** the §7 rule was applied as registered, and the ledger's `falsified`
  is the mechanical §1 mapping. The outbox already discloses all of this under UNANSWERED (3).
- **Recommendation:** whoever reads L7/L8 should read the agreement column, not the class label.
