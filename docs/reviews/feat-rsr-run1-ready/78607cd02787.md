### BLOCKER

### MAJOR

- **MAJOR-1: the warm-start vocabulary guard is skipped silently, and where it runs it checks the wrong thing.** `src/rsr/train/loop.py:375-376`.
  - **The skip.** `src_vocab = (payload.get("stream") or {}).get("vocab_documents")`, then `if src_vocab is not None and ...`. A source with no `stream` record (a default-path or corpus-size checkpoint) is therefore **accepted with no vocabulary check, and with no warning**. Probe A, case 3, gave `DEFAULT-PATH SOURCE: ACCEPTED, source_vocab_documents = None`.
  - The author discloses this in the report (item 7) but not in the code, and no test pins it. Every warm-start test in `tests/test_run1_ready.py` uses exactly this unchecked path: the `substrate` fixture is a default-path FIFO run.
  - **The wrong thing.** The check compares a *document count*, not the vocabulary. I measured the vocabulary directly at `sentences_per_document=48` (`vocab_probe.log`):
    - `build_vocab` gives **the same 172-word map** for seed 0 with 32, 64 and 256 documents, and for seed 1 with 64 documents. In every pair, 0 ids differ.
    - So the refusal the author cites, "32 vs 64 vocabulary documents", rejects a configuration whose token ids are identical. Its message, "Token ids would mean different words", is false at these knobs.
    - That does not make it a false acceptance. It means the guard stands in for the property and does not test it.
  - **Fix:**
    1. Refuse a source that records no vocabulary, unless an explicit, labelled `allow_unrecorded_vocabulary=True` is passed and stamped into `frozen` and the label.
    2. Compare the vocabulary itself. Rebuild the source's map from its recorded `stream` config and require `== vocab_map`, or record a sha256 of the vocab map in checkpoints from now on.
    3. Add a test that a default-path source is refused, and a test that a matching recorded source is accepted. The current file has no acceptance test for the recorded-vocabulary path; I exercised it only in probe A.
  - Run 1's source, arm B `ckpt-003000` (seed 0), is a stream checkpoint with `vocab_documents: 64`, so run 1 itself takes the checked path. That is why this is MAJOR, not BLOCKER.

### MINOR

- **MINOR-1: the age-only arm accepts `nu != 0`, and then its score reads content.** `src/rsr/retention/rsr.py:370-378` with `:485`.
  - Probe B case E: `psi_override="age_only", nu=0.5` builds through `build_policy`.
  - The score changes when only the gestalts change, through the redundancy term `-nu * max cos(s_i, s_j)`.
  - The label does say so (`rsr[...,nu=0.5,psi=age_only,...]`, attribution `age_only-nu`), so nothing is hidden. But the arm is then no longer "age-only" in §7.1 item 2's sense.
  - **Fix:** either refuse `nu != 0` with `psi_override="age_only"`, or have the run-1 PREREG fix `nu = 0` for both arms of the comparison and say why.
- **MINOR-2: a docstring names the wrong arm.** `src/rsr/retention/value_head.py:183` says `"content+age ~= age-only" (section 7.1) compares the content head against recency at its strongest`.
  - Under CLAUDE.md the RSR head is **content-only**: age is excluded from ψ̂, and b is off.
  - The "content+age head" is its own baseline arm (§6 A3), and it is not built here. The author's report, item 8, says so.
  - **Fix:** state that E2's comparison arms are the PREREG's to name, and that the content+age arm does not exist yet.
- **MINOR-3: the per-step §7.1 diagnostics are logged only on beat steps.** `src/rsr/train/loop.py:1152` computes `policy.step_diagnostics()` every step, but it is written only when `it % beat_every == 0` (`:1160`).
  - With `beat_every > 1`, partial ρ for every other step is computed and then discarded.
  - The run-level `diagnostics` holds the histograms only, not partial ρ.
  - The test name "...logged_every_step" holds only at `beat_every=1`.
  - **Fix:** write `diag` every step (for example to its own jsonl), or have the PREREG pin `beat_every=1` for run 1.
- **MINOR-4: a comment is stale after the P-2 pin.** `src/rsr/train/loop.py:865` still says "eps = torch's default". Also, the slice-1 test name `test_the_adamw_eps_is_torchs_default_and_recorded` (`tests/test_rsr_learning_path.py:695`) now describes a pin. **Fix:** reword both.
- **MINOR-5: the checkpoint is hashed, then read again.** `verify_warm_start` hashes the file at `src/rsr/train/loop.py:344`, and `ck.load` reads it a second time at `:365`. There is a window in which the bytes loaded need not be the bytes hashed. The T0 originals are `chmod a-w`, so the risk is low. **Fix:** read the bytes once, hash them, and load from those bytes.
- **MINOR-6: the hand union is larger than the author expects.**
  - The author expects "the same hand union as slice 1". In-process `battery_union.union(base=898628a, ours=night/2026-09-30@94a7ceb, theirs=78607cd)` refuses on **four** points:
    - the head code (slice 1's, already known);
    - three entries changed on both sides: `"rank shift counts the sliding window"`, `"observe() is never reached"` and `"the synthetic answer goes back out of band"`.
  - Slice 1 alone (`24709cb`) refuses only on the head code. Each of the three entries is an additive append to `off_gate_allowed` on both sides: night adds B1/B2 couplings and this branch adds `_r1_declare(...)`.
  - **Fix:** the integrator keeps both appends in each entry. The battery must then be re-run, because night's new couplings were never seen against this branch's code, nor this branch's against night's tests.
- **MINOR-7 (disclosed): there are no CLI flags for `pool` or `warm_start`.** `src/rsr/train/loop.py:1400-1446`. Run 1 can only be launched through `train()` (a `run.py`). That is acceptable if the PREREG's `run.py` calls `train()` directly.

### PREREG items (not defects; the PREREG must state each)

- **P-1. Which partial ρ.**
  - The spec's own words are "Partial ρ(eviction score, age) controlling for content" (§6 table, spec :530; §7.1 :577).
  - The author's reading is: content = the slot gestalts `s_i`, a linear least-squares residualisation of both rank vectors, and the full score `z(ψ̂)` (+ν term; b off).
  - That reading **does not contradict** the spec text and is defensible. It is not the only reading: `c_t` is excluded from the covariates, and the fit is linear while ψ̂ is bilinear.
  - The `vacuity.py` docstring discloses both choices. It is a diagnostic only: `grep -rn "0\.7" src/rsr` finds no comparison, only the docstring quote at `vacuity.py:10`.
- **P-2. The age-only table's learning rate.** The table sits in the `value_head` group at `base_lr / m`. That is identical to `base_lr` at d=128, since m = 1.
- **P-3. Run 1's seed must be arm B's seed 0.** The source's seed is not compared. Probe A case 5: `SEED 0 source -> seed 7 run: ACCEPTED`. The vocabulary is seed-invariant, as measured above, so the token ids are safe. But "a pool arm B never saw" is a statement about arm B's seed-0 documents.
- **P-4. The pool's offset and length**, which the author rightly did not choose. Also, sampling is with replacement (m-3), which is recorded in the config.

   - It loads only `payload["model"]` (strict) after `verify_warm_start`.
   - `ck.load(..., model=None, optimizer=None, policy=None, restore_rng=False)` at `loop.py:365`.

   - The sha256 is checked on every `train(warm_start=...)` call. A tampered byte is refused.
   - The source's path, manifest entry and sha256 are in `frozen`, so they are in the hash and the run_id. The label carries `+warm[<file>@<sha12>]`.

     - `requires_grad` is False everywhere;
     - the optimizer has one group, `value_head`;
     - after one step, 0 model tensors differ from the source;
     - φ moved.
   - The vocabulary check is MAJOR-1.
2. **Age-only head (m-8).** Probe B, below.
   - The content head receives only `(gestalts, context)`. Its ψ̂ is unchanged when `ages()` is poisoned to raise, and when ages differ wildly.
   - The age-only head receives only ages. Its ψ̂ is invariant to gestalts and context.
   - `psi_override="age_only"` together with a content `value_head` is refused. Unknown overrides (`"content+age"`, `"age"`) are refused.
   - In the age-only L_MC, gradient reaches only `table`: the gestalt and context leaves have grad `None`. The table gradient is `[0, 1.5, 3.0, 0, 0]`, which matches the hand value `2(θ-r)` at θ=(0,1,2,...) and r=(0.25 @ age 1, 0.5 @ age 2).
   - The table is a separate μP group from the transformer.
   - The one way content reaches the age-only arm's *score* (not its head) is MINOR-1.
3. **§7.1 diagnostics.**
   - The partial ρ is discussed under P-1. It is never a gate.
   - The hand-computable tests are:
     - the first-order partial formula (0.56/√0.3276);
     - average-rank ties;
     - the victim histograms {age 2, rank 3, shift 2} and {age 4, rank 1, shift 0} from a hand-set table;
     - the train-level 88 evictions per step = 2 rows × (48 − 4), all age 4, rank 1, shift 0 in warmup.
   - The per-beat-only logging is MINOR-3.
4. **Pool (m-2).**
   - The pool is selectable via `train(pool=DocumentPool(...))`.
   - `frozen["pool"]` carries offset, length, vocab_documents and ids, so two pools get two hashes (test, and probe A).

   - Pool plus `n_documents` or `stream` is refused.
5. **Constants.**
