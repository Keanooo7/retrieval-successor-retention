### MINOR

- **MINOR-A (new; test gap only): the resume refusal's boundary `top == start` is untested.** The guard is at `src/rsr/train/loop.py`, `_refuse_rows_past`: `if top is not None and top >= start`.
  - **The mutation that survives.** Hand mutation HM-G changes `>=` to `>`. `tests/test_run1_ready.py` stays **63/63 green**.
  - **Why the test misses it.** `test_a_resume_into_a_dir_with_later_rows_is_refused` (`:1576`) resumes at step 2 into a directory holding rows to step 3, so `top > start`.
  - **Why the boundary matters.** Suppose a crash comes after step `N` was drained but before checkpoint `N+1` was saved. The directory then holds rows to exactly `N`, and resuming from `ckpt-N` would write step `N` twice.
  - **The code itself is correct.** It uses `>=`. Run 1 does not resume (PREREG §11).
  - **Fix:** add a case where rows stop exactly at the resume step, or accept the gap.

### Notes

- **A truncated last row is refused with a raw error.** If a crash mid-append leaves a truncated last row in `evictions.jsonl`, a same-dir resume is refused with a raw `JSONDecodeError`, not the guard's `ValueError` (probe case 8a). It still refuses, which is safe, and a fresh-dir resume of the same checkpoint is accepted (8b). Cosmetic.
- **The FIFO default path writes neither per-step file.** Its same-dir resume is therefore never refused (probe case 6). Only `heartbeat.jsonl` can double there, and that is pre-existing.
- **Every pool arm's run_id changed relative to `c02b16d`, as intended (MINOR-1).** The tiny probe moved FIFO pool `65cd3d1dfe48bcdc` → `23969addc9adf6fb` and RSR pool `8d7b0ce1fe982604` → `0d2e1dca9d2f8e61`, while data order and final weights are identical to `c02b16d`.

  - PREREG A1.10 T12 already says only the run's own hashes count.
