## Findings

### MINOR

**m1. The §4 per-eviction jsonl loses the arm identity of kind_oldest and the five random arms.**
- **Where:** `experiments/b2-psi-probe/run.py:3306-3318`. `write_logs_jsonl` iterates `for a in names` but writes `{"gamma", "tier", **rec}`, and `rec["arm"]` is the inner policy's label.
- **What that does:**
  - `kind` and `kind_oldest` both log as `kind_oracle`;
  - `random0`–`random4` all log as `random`.
- **Measured** in `ckpt2500-seed0.logs.jsonl.gz`:
  - `(0.9,'tier2','kind_oracle')` has 65536 records;
  - `(0.9,'tier2','random')` has 163840;
  - `(0.0,'tier2','kind_oracle')` has 65536.
- **What is still correct:** the payload `attribution` is keyed by tier arm name, and `results_report.py` works around the jsonl (its `ATTR_ARMS` comment). No reported number is affected, and the units on disk still carry the correct keys.
- **Fix:** write `"tier_arm": a` in each record. Optionally regenerate the jsonl from the units.

**m2. The resume key hashes `run.py` only.**
- **Where:** `run.py:2656`, `:2933`.
- **What it omits:**
  - `src/rsr` (the model, `run_stream_with_policy`, the policies);
  - B2's LR helper module;
  - the torch version.
- **Effect:** a relaunch after a library change would silently mix units written under two code states.
- **Not exercised:** no unit was resumed in this run.
- **Fix:** add a hash of the imported `src/rsr` files (or the git tree sha of `src/`) and `torch.__version__` to `base`.

**m3. `PREREG_COMMITS` omits the TBD-1, TBD-2 and TBD-3 addenda.**
- **Where:** `run.py:105`, written to both manifests at `:2134` and `:3612`.
- **Effect:** phase B's manifest lists `e5ab398`/`2ec60dd`/`99a6626` only. It does not list `cad7b18`, `ed7fce8` or `3a90fce`, though `N_E` and `SEC_PER_ARM_DOC` come from the last two. RESULTS.md names them in prose.
- **Fix:** add the three shas.

**m4. RESULTS.md does not declare build-review F9 or F12.**
- **F9:** the random-arm seed's effective entropy is 32 bits, because `Generator.manual_seed` uses the low 32 bits (`run.py:599`).
- **F12:** §11 control 8 compares two re-runs, not the main FIT_VAL run (`run.py:~2583`).
- **Where they are now:** both are disposed of only in `~/Documents/.../B2-phaseB-fixes.md`, outside the repo.
- **Fix:** add a "known limitations" paragraph to the generator's output. It is a text change only.

**m5. `results_report.py` reads E0d from the moving ref `run/e0d`.**
- **Where:** `experiments/b2-psi-probe/results_report.py:43`, `:112-117`.
- **Effect:** re-running the generator later can change RESULTS.md's E0d section with no B2 change. The short sha is printed, which mitigates this.
- **Fix:** pin the E0d commit sha as a constant.

**m6. The history carries a red intermediate state.**
- **What happened:** `d371dce`, `b1c34a6` and the verified `a602b68` were red on `tests/test_exit_codes.py::test_every_converted_checker_exits_through_the_protocol` and on `tests/test_orch_outbox.py::test_the_committed_index_is_current`. The cherry-picks `3578f3a` and `62042b8` repaired both, and the head is green (above).
- **Effect:** a bisect over these commits will hit that red. No action is needed beyond knowing it.

**m7. The atomic writes are not durable.**
- **Where:** `_atomic_torch_save` (`run.py:3324`) and `write_logs_jsonl` use temp+replace without fsync, unlike `save_unit`.
- **Effect:** a power loss can leave a zero-length final file. That is harmless here, because all of these files are re-derivable from the units.
- **Fix:** fsync before `os.replace`, as `save_unit` does.
