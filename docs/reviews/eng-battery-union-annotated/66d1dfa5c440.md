## What was checked, and held

- **All three historical merges reproduce byte for byte with the fixed tool.** I ran the
  CLI with `--revs` and compared each output with `cmp` against the committed
  `scripts/mutation_battery.py` (literal output below). For i1, the sha256 matches the
  author's report (`ab4579c4…`).
- **The placement change does not alter the earlier reproductions.** 13ea9ae and 74dec77
  have `new constants []`, so `_insert_new_const` is never reached for them. The old
  tool (6f3f2f8) also reproduces both, and it refuses i1 with "both sides changed
  non-constant code before MUTATIONS". The placement is load-bearing for i1 only. With
  append placement patched in, i1's union is `== committed: False`, so the new rule is
  what makes 7eda821 reproduce.
- **The new constant regex does not misclassify real head code** (probes in scratch):
  - It is anchored at column 0 and needs `_UPPER` then ` = (\n`. So an annotated
    function default (`def f(_X: int = (`) remains head code.
  - A column-0 `_ALIAS: TypeAlias = (\n...\n)` is keyed as a constant. That is harmless:
    it is a module-level parenthesised assignment, and the one-sided rule applies to it
    correctly.
  - An annotation that contains `=` (`_Q: Annotated[int, Field(default=1)] = (`) does not
    match. It stays head code consistently, because `_CONST_STRIP` uses the same
    pattern.
- **Deletions can neither drop nor resurrect anything.** There are four cases:
  - ours deleted and theirs changed: refused;
  - theirs deleted and ours changed: refused;
  - theirs deleted on the `take_theirs_head` path: refused;
  - both sides deleted: stays deleted.

  An ours-deleted constant is never re-added (`ov is None and bv is not None` refuses).
  A duplicate constant or entry within one side is refused.
- **The pre-write validation is real.** `_check_output` runs inside `union()` before
  `main()` writes. It `ast.parse`s the union and re-splits it. A missing `MUTATIONS`, a
  missing closing `)`, and an unterminated last or middle entry are each `Refused` (exit
  3), not a crash. The CLI test also confirms that nothing is written.
- **The mutation's declared off-gate set is exact.** I reverted only `_CONST` through a
  pytest plugin (no repo edit). The result was `passed=25 failed=5`. The 5 failures are
  the on-gate test plus the 4 declared `off_gate_allowed` tests, with no undeclared red.
  This matches the author's "5 red, 25 green".

## Findings

**MINOR-1: a new constant is anchored on the first column-0 occurrence of its successor's
name, not on that successor's definition.**
- **Where:** `scripts/battery_union.py:298`, `re.search(rf"^{re.escape(succ)}\b", h, re.M)`.
- **What goes wrong:** if head code has any column-0 line that starts with the
  successor's name before its definition (for example `_A[0] ...`, `_A.__doc__ = ...`),
  the new constant is inserted before that line. In the probe, `_N` landed before the
  head-code line `_A[0]`. The output still parses and passes the count check, so the
  misplacement is silent. It is cosmetic unless the insertion splits a statement.
- **Fix:** locate the definition itself. Either search
  `rf"^{re.escape(succ)}(?:: [^\n=]+)? = \(\n"`, or use `h.index(o.consts[succ])`.

**MINOR-2: `_check_output` compares counts, not identities.**
- **Where:** `scripts/battery_union.py:313`.
- **What goes wrong:** a union that loses one entry or constant and gains a different one
  passes. I did not find a path in the current code that produces this.
- **Fix (cheap):** compare `set(got.entries) == set(order)` and
  `set(got.consts) == set(consts)`. Better, compare the values too: `got.entries[k] ==
  entries[k]` and `got.consts[k] == consts[k]`.

**MINOR-3: ours-only constants on the `take_theirs_head` path are still appended to the
end of the head, so the new placement rule is one-sided.**
- **Where:** `scripts/battery_union.py:276`.
- **What goes wrong:** in probe 7, `_Z` landed after `_C` at the end of the head, not
  where ours put it. The module docstring describes placement only for theirs-new
  constants.
- **Fix:** apply the mirror of `_insert_new_const` (anchor on ours' successor), or state
  the asymmetry in the docstring.
