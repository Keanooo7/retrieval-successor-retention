## MAJOR

### M-1: `resolve()` can emit "None" or a whole ledger row. The missing-key and refusal paths are untested.

**Where:** `scripts/verified_results.py:277-292`, `:21-22` and `:896-903`;
`tests/test_verified_results.py:90-97`.

The module promises (lines 21-22): "a key the table names is absent … 🔴 A missing
source is `3`, never a row with a blank in it." Two paths break that promise:

- **Null values are only rejected for `row` refs.** The null check at `:290` applies
  only to `kind == "row"`. For `kind == "top"` and `kind == "json"`, `_dig` returns
  `None` and the row renders `None`.
  - I demonstrated it by setting B1's `verdict.outcome` to null in the cache.
    `build_rows()` then rendered `` `None`; control N … True ``.
  - `--write` would exit 0 on that table.
  - The only backstop is the test's `resolve(ref) is not None`.
- **A row without `value` falls back to the whole row.** Line 288,
  `base = row.get("value", row)`, uses the entire row dict when `value` is absent.
  With an empty `sub`, the table prints the row's metadata.
  - I demonstrated it by deleting `N_ok`'s `value`. The cell became
    `{'key': 'N_ok', 'kind': 'observation', 'how': …}`.
  - `test_every_rows_source_key_exists` passes on this, because the key exists and
    the value is not None.

The tests also miss the refusal paths. `test_a_missing_source_exits_3` only covers a
nonexistent commit (`"0"*40`). No test covers:

- a missing key;
- a duplicated key;
- a null value;
- a scope quote absent from its file (`scope_line` at `:896-903`);
- an md line matched 0 or 2 times.

A mutation that disables any of those refusals would survive the suite. These are
the exact honesty properties the table exists to guarantee.

**Fix:**
1. In `resolve`, raise `Missing` when the value is `None` for every kind.
2. Allow the `row` fallback only when the row has no `value` key, its
   `kind == "statistic"`, and `sub` is non-empty. Otherwise raise `Missing`.
3. Add tests that monkeypatch `_CACHE` with a doctored ledger or file, each asserting
   `main(["--check"]) == Exit.DID_NOT_RUN`: (a) a key removed, (b) a key duplicated,
   (c) a top/json value set to null, (d) a scope quote removed from its file,
   (e) a B2 §2.1 line duplicated.
4. Add one battery mutation per refusal, for example `if n != 1:` → `if False:` in
   `scope_line`.

Current output is unaffected: every pinned value is non-null and present.

### m-7: Pins on unmerged run branches are durable only while those branches exist.

**Where:** `scripts/verified_results.py:133` and `:170`;
`tests/test_verified_results.py:7-13`.

The hard fail is acceptable today:

- Battery shards are worktrees and share the repo's objects.
- `ci.yml:18-20` checks out with `fetch-depth: 0`, which fetches all branch heads.

It is not durable. If `run/e0d` or `run/b5-convergence` is deleted, or is
squash-merged or rebased, 0e51139 or deaeaa6 becomes unreachable. On a fresh clone
this goes red on main and cannot be fixed without re-pinning. E0d's merge is
owner-blocked, so this is a live possibility.

**Fix:** keep the two commits reachable independently of the branches. For example,
push the annotated tags `verified/e0d-0e51139` and `verified/b5-deaeaa6`, or merge
with a true merge commit. State the rule in the test docstring. Creating tags is the
author's call, not the reviewer's.
