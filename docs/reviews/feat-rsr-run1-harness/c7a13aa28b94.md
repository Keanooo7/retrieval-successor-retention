## (2) No exit code changes

**How `status()` behaves.** `status()` is defined in `src/rsr/exit_codes.py`.

- It refuses a `bool`, `None`, a value that is not an int, and an int outside 0–5.
- For any other value it returns `Exit(code)`.

**What measure-seed can return.** At `run.py:4054`, `doc["exit"]` is always `int(code)` of an
`Exit` member. It is set by `measure_seed.done()`, and the possible values are 0, 1, 3 and 5.

**What finalize can return.** `finalize()` has a single `return code`. That `code` is
`Exit(worst["exit"])`, so it is already an `Exit`.

**Measured.** I compared `status(v)` with `Exit(v)` for every possible input:

- `all(status(v) is Exit(v) for v in 0..5)` gave `True`;
- `all(status(e) is Exit(int(e)) for e in Exit)` gave `True`;
- the values 0, 1, 3 and 5 map to `OK`, `FAIL`, `DID_NOT_RUN` and `INERT`.

`run_main` already wrapped `main()` in `status()`, so the process status was identical before the
fix and is identical after it.

**Shadowing.** The new module-level name `status` is shadowed by local variables in
`measure_seed` (`:2901`, `:2992`) and in `finalize` (`:3116`). Neither function calls `status()`.
The only calls are at `:4054` and `:4063`, inside `main()`, which has no local of that name.
