## (e) B04 is redundant: agree

**The mutation.** B04 turns off `if i < len(lines) and odd(lines[i]) and not lines[i].strip()`.

**Why it cannot change the outcome.**
- The blank-skip loop stops at a whitespace-only line that holds a non-`\n` break.
- Every character in `OTHER_LINE_BREAKS` satisfies `str.isspace`, so such a line strips to empty.
- The table loop then needs `startswith("|")`, so the table is empty, the header check fails, and
  the result is `malformed` either way.
- Only the problem text differs.

**Measured.** I built the mutant in memory with `ast` (no file touched) and compared it with the
original on **20,513** generated texts: every break × every gap position, and 20,000 random
insertions of breaks, fences, pipes and tabs. **0 differences** in `(status, values)`
(`b04_fuzz.py`).

## New findings

### MINOR-N1: an exit-1 finding stops the seed before C2, C3 and C8, so A3d.2's "the order spans arms and controls (C1–C8, C10)" does not hold for them

- `run.py:2740` sets `stop` on any arm, C5-inconclusive or C6 finding. C2, C3, C8, C4 and C7 are
  computed only after it (`:2753ff`).
- So an inconclusive seed whose pairing is broken reports **`failed` / 1**, a valid measurement whose
  check failed. A3d.2 and the inert-exit-5 ruling make it **3**, because the measurement is not
  valid. Measured above.
- C2, C3 and C8 read only artefacts and checkpoints. They need no EVAL pass.
- **Fix:** evaluate C2, C3 and C8 before honouring an exit-1 stop. Alternatively, have A3d state
  that C2–C4, C7 and C8 are not evaluated once an exit-1 finding stops a seed.

### MINOR-N2: fence tracking ignores fence character and length (residual of MINOR-A3d-1(a))

- `_FENCE` (`run.py:880`) toggles on any line starting with ```` ``` ```` or `~~~` (`:914-918`).
- In CommonMark, a fence closes only with the same character and at least the same length.
- So a table quoted inside a ```` ```` ```` block that contains an inner ```` ``` ````, or inside a
  `~~~` block that contains ```` ``` ````, parses as **`filled`**. Measured above.
- Like MINOR-A3d-1, this needs a malformed Amendment 4. Values that differ are still caught by
  C10's cross-check with `launch-git.json`.
- **Fix:** track the opening fence's character and run length.

### MINOR-N3: the fence-aware count departs from A3d.1 rule 1

- A3d.1 rule 1 says the heading "must appear **exactly once in the whole file**".
- At `d86af31` the parser counts only lines outside fences (`run.py:926`). A fenced copy plus the
  real table gives `filled`.
- At `a811714`, and in the A3d review's probe, the same text gave `malformed`.
- The new reading is reasonable and reads the real table, but it is not the registered rule.
- **Fix:** align one of the two: an A3d sentence, or count fenced copies too.
