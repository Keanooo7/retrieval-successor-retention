## MAJOR

### MAJOR-1: the run ledger misstates `seeds_actually_run` and `steps_done` whenever a seed did not run or an arm crashed

**Where.**

- `run.py:2470-2475` writes `seeds_actually_run=run["seeds"]`. That is every seed that has a
  measure doc, whether or not anything ran.
- It writes `steps_done=min(steps)` over C6 rows. C6 exists only for seeds whose arms all
  completed (`run.py:2269-2275` returns before C6), so a crashed seed contributes nothing to the
  minimum.
- At seed level, `run.py:2215-2216` sets `steps_done=None` and `seeds_actually_run=[]` for any arm
  outcome that is not OK. The steps that were recorded are dropped: the heartbeat's last beat.
- **A3b.3** requires `steps_done` and `seeds_actually_run` "as actually recorded. Neither may be
  cleared." These fields are its answer to the review's objection that `did_not_run` "hides that
  training ran".

**Evidence.** Real processes, `ledger_probe.py` and `status_probe.py` in the scratchpad:

| case | per-seed doc | `finalize` → ledger |
|---|---|---|
| seed 0 completes (4 steps); seed 1's launcher never ran (no `launch-git.json`) | seed 1: `did_not_run`, `steps_done None`, `seeds_actually_run []` | exit 3, status `did_not_run`, **`seeds_actually_run [0, 1]`**, **`steps_done 4`** |
| seed 0's psiC crashes after 2 steps (real crash line, rc 1); seed 1 completes | seed 0: `crashed`, `steps_done None`, `seeds_actually_run []` | status `crashed`, **`seeds_actually_run [0, 1]`**, **`steps_done 4`** |
| an age arm killed by SIGTERM through zsh `wait` (rc 143) after 35 beats | `crashed`, `steps_done None`, `seeds_actually_run []` | — |

**Fix.**

- Build `seeds_actually_run` from seeds whose arms actually trained. Use each doc's own field,
  extended to crashed arms.
- Take `steps_done` per arm from the heartbeat's last beat, or from the result's `steps_done`, for
  every arm with a heartbeat. Never take it from C6 only.
- Add a test with one crashed seed and one seed that did not run.

### MAJOR-2: C10 does not compare the owner values with Amendment 4, as A3.7a requires

**Where.** A3.7a (`PREREG:2053-2054`): "Each owner value is compared both with `launch-git.json`
**and with the value the owner registered in Amendment 4**."

`c10_launch_values` (`run.py:1635-1784`) compares the recorded values only with `OwnerValues`. Those
come from the operator's `measure-seed` and `finalize` arguments (`run.py:3178-3188`). No code reads
the PREREG for the owner values.

**Why it matters.** Suppose the launch used a mistyped `GAMMA` and the same value is typed into
`measure-seed`. C10 then passes, and RESULTS prints the mistyped value as "owner values". That is
the case the A3.7a clause exists to catch.

**Fix.**

- Extract A4's slot table from `PREREG.md` with a pinned heading, as `LAUNCHER_HEADING` does.
- Refuse (exit 3) unless the CLI owner values equal it.
- Test the extraction on a synthetic PREREG.

A4 does not exist yet. So either the table format is fixed with the PREREG author now, or this lands
before the first `measure-seed`. Until then, the harness does not implement A3.7a.

## MINOR

### MINOR-1: an arm-level tie between two exit-3 arms is settled by arm order, which is not registered

- `run.py:2274` takes `max(bad, …)`, which returns the **first** arm in (psiC, fifo, age) order
  among those with equal rank.
- A3b.3 and A3b.5 register a tie rule only across **seeds** (the lowest seed).
- Measured with real processes (`status_probe.py`):
  - fifo `WarmStartRefused` (rc 1, no heartbeat) plus psiC mid-loop crash (rc 1, crash line) →

- Both notes are written either way, and nothing gates on the word.
- **Ask the PREREG author** to register a rule, for example "`crashed` over `did_not_run`". The
  builder raised this too.

  Otherwise it falls through to `crashed`.
- `classify_rc` says "rc 3: reported as itself".

- A3b.3's row reads "an arm's rc 3 → `did_not_run`". The ruling names `invalid` "3, not a valid
  measurement". The process did not crash.
- **Fix:** rc 3 with a heartbeat → `did_not_run`, note `ARM_DID_NOT_RUN (liveness invalid)`, and a

### MINOR-4: `measure-seed --dry-run` cannot read the only dry run launcher v4 allows

Launcher v4 permits a dry run only at `STEPS=0` (A3b.1). Against that:

- `validate_owner_values` refuses `iters < 1` (`run.py:356`). Measured: `measure-seed … --iters 0
  --dry-run` gives rc 3, "iters=0: a positive integer run length".
- Bypassing that, `Run1Config.snapshots` at CKPT = 0 raises `ValueError: range() arg 3 must not be

- The orchestrator root is not settable from the CLI (`run.py:303`, `:3208`), and a foreign
  `RSR_ORCH_ROOT` is refused even under `--dry-run` (`run.py:766`). So a dry run's job records in

A3.12 says `measure-seed --dry-run` exists for dry runs. As built it cannot run against one, which
is why C10 had only ever met constructed records (the builder's "believed, not verified").

**Fix.** Let `--dry-run` accept `iters 0` (no snapshots) and an isolated root, recorded in the doc,
with C10 still failing on `dry_run`.
