### MAJOR-4: `stamp()` overwrites any existing `rsr_env`, which breaks the docstring's own claim and fails I2 once combined

- `scripts/battery_env.py:10-12` claims: *"rows merged from several batteries each keep the environment they ran in."*
- But `stamp` (`:188`) does `{**row, "rsr_env": dict(env)}`. That replaces a row's existing stamp with the stamping process's environment. Measured: a row carrying `{'RSR_BATTERY_THREADS': '2'}` comes out as `{'RSR_GIT': '/merge/proc'}`.
- I2 (`eng/i2-sharding` @ `fc339ea`, `scripts/battery_shards.py::report`) calls `mb._report` on the merged shard rows. So the merged record would carry the merge driver's environment, not each shard's. That path also writes the JSON without ever calling `check()`.
- Measured on a scratch tree of I6 head plus I2's three new files:
  `FAILED tests/test_battery_shards.py::test_merged_rows_are_in_table_order_with_the_serial_schema`.
  Its `_serial()` is `json.dumps(rows, indent=2)` and the file now has `rsr_env`. The test passes on I2 alone.
- **Fix:** have `stamp` keep an existing `rsr_env`, for example `row.get("rsr_env", dict(env))`, or stamp in `_row` at the time the row is produced. Tell the I2 author that `_serial` must follow the schema. Whichever branch lands second must fix this.
