## Findings

### MINOR-1 (required): the inventory's file set depends on each machine's git excludes; the code and fixture claim a repo ignore rule that does not exist

**Where:**
- `scripts/battery_env.py:301-303`: *"git-ignored files -- `/.claude/worktrees/` (`.gitignore`), `*.local.json` -- still are not"* read.
- `scripts/battery_env.py:155-156`: *"Non-ignored files are the same set in a checkout and in a battery shard, except the author's own not-yet-added files."*
- `scripts/battery_env.py:311-320`: `ls-files --cached --others --exclude-standard`.
- `tests/test_battery_env.py:341`: the fixture `.gitignore` is `"/.claude/worktrees/\n*.local.json\n"`.
- `tests/test_battery_env.py:380-393`: the test that relies on that fixture.

**Facts:**
- The repository's `.gitignore` has no `local.json` rule (`grep -n local.json .gitignore` → rc 1). Its only `.claude` rule is `/.claude/worktrees/` (`.gitignore:82`).
- On this machine, `.claude/settings.local.json` is ignored by `~/.config/git/ignore:1` (`**/.claude/settings.local.json`; `git check-ignore -v`).
- The main checkout has that file (467 bytes; no `RSR_*` today).
- The common dir's `info/exclude` holds a machine-local `claude-code-runtime` block that ignores more `.claude/*.json` runtime files. Those are also scanned suffixes and also in `SCANNED`.

**Measured (What I ran, 5):**
- **Setup:** a fresh `git clone` of this head, with an untracked `.claude/settings.local.json` holding a permission rule that uses a typo'd name, `Bash(RSR_BATTERY_THREAD=2 uv run pytest:*)`.
- **Run:** `test_inventory_every_rsr_name_the_tree_reads_is_declared` in that clone:
  - with this machine's git config: rc 0, `passed=1`;
  - with `HOME`/`XDG_CONFIG_HOME` pointing to an empty directory (no global excludes, as on another developer's machine): rc 1, `passed=0 failed=1`, with `AssertionError: ... {'RSR_BATTERY_THREAD': ['.claude/settings.local.json:1']}`.
- **Control:** the same file in a clone at `c680390` (tracked-only), with no global excludes: rc 0, `passed=1`.

**Consequence (graded by it):**
- **Not affected:**
  - the refusal: `check()` reads `DECLARED`, not the inventory;
  - battery shards: `git clean -ffdxq` at creation and at every reset, and a shard has no `settings.local.json`;
  - CI: a fresh checkout has no untracked files.
- **Affected:** the inventory test's verdict in a developer's main checkout. On the same tree and SHA, it can now be red on one machine and green on another. That is the property the second review's MAJOR-1 fix bought, and the `SCANNED` docstring still asserts it.
- **Direction:** loud only. `--others` makes the scanned set a superset of the tracked-only set, so no machine can see *less* than before.
- **Why it must still be fixed:** the fixture writes into its own `.gitignore` a rule the repository lacks. As a result, `test_inventory_skips_ignored_files_in_a_checkout_and_a_worktree` proves the skip under an ignore configuration the real tree does not have. The author disclosed the environment dependence in the report ("Not verified" item 3), but the code comment at `:302-303` still states it as a repository fact.

**Fix (pick one):**
- **(a), minimal:**
  - add `/.claude/settings.local.json` (or `/.claude/*.local.json`) to the repository's `.gitignore`;
  - make the fixture's `.gitignore` in `_repo` use the same pattern as the real file, rather than a broader `*.local.json`;
  - correct `battery_env.py:155-156/301-303` to say that the other ignore sources (`core.excludesFile`, `info/exclude`) still differ per machine.
- **(b), structural:** scan `--others` only in `src scripts experiments tests ops`, not in `.claude`. `.claude/` is where Claude Code writes machine-local runtime state; a new source file lands in the other five directories. This removes the surface rather than enumerating it. It needs one extra `ls-files` call or an `:(exclude)` pathspec, plus a test that plants an untracked non-ignored `.claude/x.json` and expects it to be skipped.

### MINOR-2 (optional): the `show-toplevel` comparison is case-sensitive on a case-insensitive filesystem, and its `.resolve()` is untested

**Where:** `scripts/battery_env.py:305-306`: `Path(top).resolve() != Path(root).resolve()`.

**Measured (What I ran, 6-7):**
- Called directly:
  - `tracked(Path("/users/keanooo7/…/i6-env-record"))` (lower-case `/users`) raises `RuntimeError … is not the top of a checkout (its checkout's top is /Users/…)`. So does `.WORKTREES`. APFS is case-insensitive and `Path.resolve()` does not canonicalise case.
  - A relative root, a `/tmp` → `/private/tmp` symlink, a trailing slash, a symlink to the clone, and a worktree (`.git` as a file) are all accepted correctly.
- The one real caller is unaffected: pytest run from a lower-case `cd /users/…` gives `passed=1`, rc 0.
- A delete-a-line probe that drops both `.resolve()` calls leaves `tests/test_battery_env.py` at `passed=24`, rc 0. The symlink handling therefore has no test, but the one caller already passes a resolved path.

**Fix:** `os.path.samefile(top, root)`. It compares inodes, so it handles case and symlinks in one call. Or leave it: the only failure is a loud false refusal for a caller that does not exist today.

## Attack results (the brief's five points)

### 1. Machine dependence of the inventory

- **Can it differ between machines?** Yes, as MINOR-1.
- **Can it differ between a shard, CI and a fresh clone?**
