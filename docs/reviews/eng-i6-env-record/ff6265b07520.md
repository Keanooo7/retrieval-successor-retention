## Findings

### MAJOR-1: the inventory scans `.claude/worktrees/`, so the suite is red in any checkout that holds an agent worktree of a post-I6 tree

- **Where:** `scripts/battery_env.py:140` sets `SCANNED = (..., ".claude")`. Line 246 then walks it with `(root / top).rglob("*")`. The only exclusions are `test_*`, `*.local.json`, `.venv` and `__pycache__`.
- **What gets scanned:** `/.claude/worktrees/` is git-ignored (`.gitignore:82`). Claude Code puts full checkouts there for agents run with `isolation: worktree`, and the main checkout has 11 today.
- **Why it goes red:** a copy of `scripts/battery_env.py` inside one of those worktrees has the relative path `.claude/worktrees/<id>/scripts/battery_env.py`. That is not `_SELF`, so it gets scanned. Its own docstring (`:34`) contains the deliberate typo `RSR_BATTERY_THREAD=4`, which is undeclared.
- **Reproduced (What I ran, 9):** control `passed=1`. With one copied file, `FAILED tests/test_battery_env.py::test_inventory_every_rsr_name_the_tree_reads_is_declared - AssertionError: ... {'RSR_BATTERY_THREAD': ['.claude/worktrees/agent-demo/scripts/battery_env.py:34']}`.
- **Other agent code gets scanned too:** stale agent worktrees add their `src/`, `scripts/`, `tests/_*.py` and `ops/` files to the inventory. So the test can go red for a name some old branch used.
- **Measured today:** 88 files and 36 tokens under the main checkout's `.claude/`, with 0 undeclared, taking 7.4 s (What I ran, 8). So it is green now by coincidence.
- **Does not affect the battery:** shards are clean `git worktree`s with no ignored content.
- **The deeper problem:** the test's result depends on ignored, machine-local content. That is exactly what the round-1 MINOR-7 fix should not have brought in.
- **Fix:**
  - Enumerate files with `git ls-files` under `SCANNED`, so only tracked content counts and a checkout and a shard see the same set.
  - Or at least limit `.claude/` to the top-level `settings.*.json` and skip any directory that contains a `.git` entry.
  - Add a case to `test_inventory_finds_a_name_by_file_and_line` with a `.claude/worktrees/x/scripts/a.py` holding an undeclared name, and assert it is **not** found.

### MAJOR-2: per-row `rsr_env_suite` makes serial and sharded rows unequal when verdicts are equal (I2 goes red when combined)

- **Where:** `scripts/mutation_battery.py:6217` stamps every row. `scripts/battery_env.py:225-235` is `stamp`.
- **Why the rows differ:** `rsr_env_suite` holds `RSR_ORCH_ROOT` (the shard's root) and `RSR_BATTERY_PROBE` (its probe path). Both are different for every pool, so the rows differ between any two batteries at one SHA, even two serial ones. I2's `run_shard` also exports `RSR_BATTERY_THREADS` (`battery_shards.py:234`), so `rsr_env` differs too.
- **Measured on `git archive ff6265b` plus I2's three files at `02236f3`,** with `mutation_battery.py` merged in-process by `battery_union.union` (What I ran, 11-14). The result was `passed=93 failed=2`:
  - `FAILED tests/test_battery_shards.py::test_sharded_verdicts_equal_the_serial_ones_on_the_stub`. The assertion is `json.loads(merged) == json.loads(serial)` (`tests/test_battery_shards.py:685` on I2). At index 0, the sharded row has `'rsr_env': {'RSR_BATTERY_THREADS': '1'}` and `'rsr_env_suite': {'RSR_BATTERY_PROBE': '.../work/shard-0-of-2/pool/probe-0.json', ...}`.
  - The second failure, `test_command_accepts_a_committed_entry_point`, is an artifact of the archive: it has no `.git`. It fails the same way on I2 alone.
  - **Control:** I2 alone, `passed=1` for the serial test.
  - **Cause confirmed:** with I6's own mutation "the --json rows drop the RSR_* environment" applied, the combined file is `passed=44 failed=0` (What I ran, 14).
- **The first round's MAJOR-4 test does pass now.** `test_merged_rows_are_in_table_order_with_the_serial_schema` is green in the combined tree. This is a sibling failure that the author did not test ("I2 compatibility was not tested").
- **This is the PLAN's I2 contract.** "A serial and a sharded run at one SHA can be compared mutation by mutation" is what I2 exists for. Whole-row equality stopped holding because of I6.
- **Also:** I2's `merge_rows` builds its `DID_NOT_RUN` rows with `mb._row`, which has no `rsr_env` keys. The merged record therefore mixes stamped and unstamped rows. That is harmless today, because `row_problem` only requires `_row`'s keys.
- **Fix:** one of these, decided before the second of I6 and I2 lands on night:
  - (a) **In I6:** keep per-run values that are specific to one shard (`RSR_ORCH_ROOT`, `RSR_BATTERY_PROBE`) out of the verdict row. Record them in stdout or a sidecar file. Then name the row keys that are provenance rather than verdict.
  - (b) **In I2:** compare rows with `rsr_env` and `rsr_env_suite` projected out, and state that contract in both docstrings.
- **My recommendation:** (a) plus a sentence in `battery_env.py`. Two batteries at one SHA should produce equal verdict rows, and a shard path makes that false by construction.

### MINOR-3: `rsr_env_suite` is a snapshot taken once, but each `run_suite` rebuilds the environment it actually uses

- **Where:** `scripts/mutation_battery.py:6187-6188` computes `suite` once, before the baseline. `run_suite` (`:5939`, then `:5946`) calls `_suite_env()` and `iso.shard_env` again for every suite.
- **Why they can drift:** `_suite_env()` reads `suite_threads()`, which reads `ROOT/ops/lanes.json`. That file is in the invoking tree, not the shard, and the tree is checked clean only at the start. It also reads `os.environ` again.
- **Measured (What I ran, 10):** the real `_run_isolated` and `run_suite` were called in-process, with only `_spawn`, `open_workspace`, `reset` and `suite_problem` replaced. `ops/lanes.json` was edited between the baseline and the mutation. Result:
  - recorded `RSR_TORCH_THREADS: 1`, the baseline's `Popen` had `1`, the mutation's `Popen` had `6`;
  - `recorded == mutation's actual: False`.
- **The docstring overclaims:** `scripts/battery_env.py:13-15` says the field is "the environment the shard's pytest actually receives".
- **This is the MAJOR-3 caveat the author disclosed (Not-done item 4),** now with a concrete way to trigger it. Nothing reads `RSR_TORCH_THREADS` today, so the impact is small.
- **Fix:** build the suite env once in `_run_isolated`, pass it into `run_suite`, and stamp that same object, so the record equals what was used by construction. Or have `run_suite` return the env it passed to `_spawn`.

### MINOR-4: the stated rationale for the `_run_isolated` check is false for I2
