## Findings

### MAJOR-1: the `<probe>` substitution is unproven — the fake shard puts the probe inside the root, the real pool does not

- **Where:**
  - `scripts/battery_env.py:254-257`: `subs = [(str(probe), PROBE_TOKEN), (str(root), SHARD_TOKEN)]`.
  - The only location-independence test is `tests/test_battery_env.py:230` `test_rows_do_not_depend_on_where_the_shard_lives`. It builds its shard with `_one_mutation` → `use_fake_shard` (`tests/_battery_fakes.py:19`: `iso.Shard(root, ..., root / ".battery-probe.json")`).
- **Why the gate is empty:** in that layout `str(root)` is a prefix of the probe path. When the probe substitution is deleted, the root substitution still turns `RSR_BATTERY_PROBE` into `<shard>/.battery-probe.json`, which is location-independent. So the test passes.
- **The real layout:** `open_workspace` builds `Shard(path, sha, index, pool / f"probe-{index}.json")` (`scripts/battery_isolation.py:328`), with the probe outside `pool/shard-k`. Without the probe substitution, a real row carries `RSR_BATTERY_PROBE='<pool>/probe-0.json'`, the pool's absolute path. The pool is `~/.cache/rsr-battery/<repo>` for a serial run and `work/shard-k-of-n/pool` under I2. So a serial row and a sharded row differ by construction. That is exactly the second review's MAJOR-2.
- **Measured (What I ran, 6-8):**
  - I deleted the line `        (str(probe), PROBE_TOKEN),` in the worktree. `tests/test_battery_env.py` gave `passed=22 failed=0`, rc 0. All 27 battery-referencing files gave `passed=1176 failed=0 skipped=0 errors=0`, rc 0.
  - Control: a copy of the gate test that uses the real layout (probe at `pool-x/probe-0.json`, root at `pool-x/shard-0`) passes at head (rc 0) and fails under the deletion (rc 1, `AssertionError` at `rows[0] == rows[1]`).
- **Round-2 history:** the round-2 commit message (`9f2d23e`) says *"the `<pool>` token also swallowed the shard root (probe.parent == root in the fake shard ...)"*. The author dropped the pool token so that the root token could be tested. The same fake layout makes the probe token untestable, and the comment at `scripts/battery_env.py:250-253` says the probe "is a file in the pool". The code is right; the proof does not reach it.
- **Fix (test-only, plus one table entry):**
  - In `test_rows_do_not_depend_on_where_the_shard_lives`, build each shard the way `open_workspace` does: `root = pool/shard-0`, `probe = pool/probe-0.json`. That means a local `iso.Shard(...)` plus the same `open_workspace`/`reset` monkeypatches that `use_fake_shard` applies. Do not change `_battery_fakes`, which other gates use.
  - Add the mutation `"battery-env: rows carry the probe's path"`. Its anchor is `"        (str(probe), PROBE_TOKEN),\n"` → `"        # (probe not replaced)\n"`, with the gate `test_rows_do_not_depend_on_where_the_shard_lives`.
  - Keep `str(tmp_path) not in json.dumps(rows[0])`: that assertion is what catches a pool path.

### MINOR-2: `tracked()` does not raise for a directory that is not a checkout but sits inside one

- **Where:** `scripts/battery_env.py:279-292`. The docstring says it *"Raises `RuntimeError` when `root` is not"* a git checkout.
- **What actually happens:** `git -C root ls-files` exits 0 whenever `root` is anywhere inside some repository. Two cases:
  - An untracked or ignored copy of the tree inside another checkout (for example a `git archive` extracted under `runs/` or `.claude/`) returns `[]`.
  - A tracked subdirectory of a checkout returns `[]` too, because the `SCANNED` pathspecs are resolved relative to it.
- **Measured (What I ran, 10):** in a scratch clone, `tracked(<clone>/nested-copy)` returned `[]` and `inventory` returned `{}` with no raise. The same held for `tracked(<clone>/src)`, which gave `n = 0`.
- **Impact:** small. The only caller is `test_inventory_every_rsr_name_the_tree_reads_is_declared`, and its `len(found) > 12` still goes red. But the stated guarantee is false, and `test_inventory_refuses_a_tree_that_is_not_a_checkout` passes only because pytest's `tmp_path` is not inside a repository.
- **Fix:** in `tracked()`, check that `git -C root rev-parse --show-toplevel` resolves to `root.resolve()`, and refuse otherwise. Or weaken the docstring to what is true.

### MINOR-3 (optional): a new, not-yet-`git add`ed file that reads an `RSR_*` name is invisible to the inventory

- **Where:** `scripts/battery_env.py:284` (`ls-files` without `--others`). `tests/test_battery_env.py:362` asserts that an untracked `scripts/untracked.py` is not read.
- **Measured (What I ran, 9):** an untracked `scripts/zzz_new_tool.py` holding `RSR_ZZZ_UNTRACKED` left the inventory test at rc 0 `passed=1`. An uncommitted edit to the tracked `scripts/orchestrator/lanes.py` was seen correctly: rc 1, `{'RSR_ZZZ_TRACKED_EDIT': ['scripts/orchestrator/lanes.py:529']}`.
- **Effect:** the author's local pre-commit run is green, and CI and the next battery baseline go red after the commit. That is later detection, not a hole. Tracked edits made in a shard by a battery mutation are inventoried, and no table mutation's `new` text adds an `RSR_*` token (What I ran, 5).
- **Possible fix:** `--cached --others --exclude-standard`. It still excludes the git-ignored `.claude/worktrees/` and `*.local.json`, so MAJOR-1 of the second review stays fixed. A shard has no untracked files, so a checkout and a shard differ only by the author's own in-progress files. This is a design choice the author made deliberately, so it is not required.

## Attack results (the brief's six points)

1. **`git ls-files`: where it runs, and races**
   - **Who calls it:** only the inventory test (`inventory` → `tracked`). The battery, `main()`, `_run_isolated`, shards and verifiers never call it.
   - **Where that test runs:**
     - a main checkout: fine;
     - a battery shard, a worktree whose `.git` is a file: fine, and covered by the author's test and by `open_workspace`'s worktrees;
     - CI: `actions/checkout@v4` with `fetch-depth: 0`, so `.git` exists and `_git_bin` falls back to `which git`.
   - **Trees with no `.git`:** I found no copy step in `scripts/`, `src/`, `tests/`, `ops/` or `.claude/` that makes one for the suite (`git grep "git archive\|copytree\|rsync"`; the only hits are the hooks' deny-lists and one `copytree` of `runs/`). The `git archive` review method now fails this test; that is disclosed, and `test_command_accepts_a_committed_entry_point` already needed `.git`.
   - **cwd:** `-C str(root)` is correct, and paths are relative to `root`.
   - **Tracked but uncommitted edits:** read from the working tree, so they are inventoried (MINOR-3 above).
   - **Races:** `ls-files` only reads the index of its own worktree. It is not a `worktree add/remove/list` admin operation, so it is outside I2's `worktree_admin_lock` domain and cannot race it. The test's own `git worktree add` runs on a throwaway repository under `tmp_path`, with its own common dir, not the real repository's. Between suites the battery resets the shard only after the suite's process group has been killed (`_spawn`/`_kill_group`), so nothing writes that index while `ls-files` reads it.
2. **`run_suite(shard, env=None)` and `suite_env()`**
   - **Call sites** (`git grep` here and in I2's `02edc5b`, read-only):
     - `_run_isolated` passes one `env` to the baseline and to every mutation (`scripts/mutation_battery.py:6231/6235/6253`);
     - `tests/test_battery_isolation.py:241` and `tests/test_battery_reasons.py:126` use the default path, which is unchanged in behaviour;
     - every stub in the tests takes `*a` or `env=None`;
     - `battery_subset.py` and I2's `battery_shards.py` go through `mb.main()` and never call `run_suite` or `_run_isolated`.
   - **What the env contains:** `_suite_env()` (os.environ, the census redirect, and the thread cap from `RSR_BATTERY_THREADS` or `ops/lanes.json`), plus `shard_env` (fixed per shard). None of it needs rebuilding per mutation.
   - **Mutation:** `Popen(env=...)` does not mutate the dict.
   - **Timing of a bad thread cap:** `suite_threads()` can refuse (bad `RSR_BATTERY_THREADS` or `lanes.json`). It now does so before the baseline rather than at it; `main()` already calls it earlier, so nothing observable changes.
3. **The `<shard>`/`<probe>` substitution**
   - **Path forms:** `RSR_ORCH_ROOT` and `RSR_BATTERY_PROBE` are written by `shard_env` from `str(shard.root)` and `str(shard.probe)` (`scripts/battery_isolation.py:191-192`), the same objects `portable` is given. So a `/tmp` vs `/private/tmp`, symlink or trailing-slash mismatch cannot arise.

   - **The defect:** the only defect is MAJOR-1 (the probe token is untested under the real layout).
   - **Observation, not a finding:** `rsr_env`, the battery's own environment, is not tokenised. If a launcher exports `RSR_ORCH_ROOT` (tick or launchd), the row carries the invoking tree's path. That is where the battery ran, not where the shard lives, and I2 compares verdict fields only.
