## Findings

**MAJOR-1: finding 1 states "filler is higher on every seed" for evicted sentences. That
is false on seed 2.**
- **Where:** `docs/RESEARCH-CONTEXT.md:845-847`.
- **The numbers:** in `B.ckpt3000.F1.D.age_gt_M|*`, seed 2 has pending 0.0829 and filler
  0.0757, so pending is higher. The numbers printed on the same line show it.
- **Why it matters:** this is a false sentence in the orientation document, and it
  inflates the age-dependence story that this finding exists to state carefully.
- **Fix:** "filler is higher on seeds 0 and 1 (0.0962 vs 0.0843; 0.0817 vs 0.0544); on
  seed 2 pending is higher (0.0829 vs 0.0757)."

**MINOR-1: the monotonicity parenthesis is incomplete.**
- **Where:** `docs/RESEARCH-CONTEXT.md:838`, "(not monotonically on seed 1)".
- **The ledger shows:**
  - seed 0's gap is monotone non-increasing from age 1 to 16;
  - seed 1 rises at 1→2 and again at 7→10;
  - seed 2 also rises at 1→2 (+0.0432 → +0.0452).
- **Fix:** "(monotonically only on seed 0)".

**MINOR-2: finding 2's heading reaches past the two ε values measured, and coupled L2
contradicts it as written.**
- **Where:** `docs/RESEARCH-CONTEXT.md:862`, "`β`'s inertness under AdamW … holds only as
  `ε → 0`".
- **Why it overreaches:** B1 measured ε ∈ {1e-8, 1e-12}. The limit statement is an
  extrapolation. The mechanism is plausible, but the ledger does not show a limit.
- **The contradiction:** the list under the heading includes coupled L2, which is LIVE at
  both ε (`:878`). A reader will take that as a counterexample to "holds as ε → 0". It is
  one only if coupled L2 is read as "AdamW", which it is not: it is Adam with L2 folded
  into the gradient.
- **Fix:** "`β`'s inertness … fails at ε = 1e-8 and holds at ε = 1e-12 in the three
  decoupled-decay arms (the two ε B1 measured); coupled L2, which is not AdamW, is LIVE
  at both."

**MINOR-3: the RESULTS note does not say that a re-run will no longer reproduce the
committed `config_hash`.**
- **Where:** `experiments/carry-forward/RESULTS.md:104`.
- **Why it matters:** `FALSIFIER` is written into `manifest()` (`run.py:913`), and
  `scripts/ledger.py:439` hashes the manifest. A reproduction of carry-forward from this
  commit onward therefore gets a different `config_hash` from
  `runs/carry-forward/ledger.json`, by design. A future verifier comparing hashes would
  see a mismatch with no explanation.
- **Fix:** add one clause: "a re-run's `config_hash` therefore differs from the committed
  ledger's; that is this text change, not a config change."
