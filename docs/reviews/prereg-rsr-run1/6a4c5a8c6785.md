## (c) MAJOR-3's resolution vs correction 20. The evidence both ways; this review does not decide

Correction 20 (`docs/spec-corrections.md:417-426`) reads:

> "`attn_dropout: float = 0.2` … during training `α` is stochastically zeroed and a slot can score
> zero demand because a mask fell on it — noise in a *policy-relevant* direction. **Eval mode for
> the retention target; train mode for the LM loss**, as an explicit mode switch in the code rather
> than an ambient default. D-F."

**For "C-1 is consistent with correction 20":**

1. **The retention clause is satisfied.** `r_i` remains eval-mode. C-1 keeps L1(a)'s eval forward
   as the `r_i` source (`PREREG:997-998`).
2. **The correction's own rationale extends to `s_i`.** It objects to dropout noise "in a
   policy-relevant direction". Under C-1 the noise removed is exactly in what the policy reads
   (`s_i`). The signed ADR-0009 L2 already extended the same rationale beyond `α`, to `c_t`.
3. **There is no optimised LM loss to protect.** "Train mode for the LM loss" serves dropout's
   regularising role in the update. Under D2(b) (ruled "Frozen (no `L_NTP` update)"), `loop.py:1239`
   sets `objective = None`, so `L_NTP` reaches no parameter. It is only reported. The correction
   was written before any frozen configuration existed (D2 was ruled 2026-09-30).
4. **The "explicit mode switch" form is honoured.** C-1 is a named flag, recorded in `frozen`, the
   config hash and the label, and refused without freeze (`PREREG:987-995`).
5. **It matches the substrate's measured regime.** Every measurement that selected or
   characterised the substrate ran the model in `eval()`. Checked:
   - S0-03 `answer_readout` (`experiments/s0-03-rewardable-corpus/run.py:201-202`), which is C4's
     and fresh-stream's R instrument;
   - B2 (`experiments/b2-psi-probe/run.py:783`, `:1172`, `:1663`).
6. **Pairing is unaffected.** Eval mode applies to every arm. This is unlike ADR-0009's rejected
   L1(b) (`attn_dropout = 0` on RSR arms only).

**For "C-1 departs from correction 20, or needs the owner":**

1. **The literal text has no "if optimised" condition.** Under C-1 the reported `L_NTP`
   (`loss_lm`, every step) is computed in eval mode. That is the reverse of "train mode for the LM
   loss". CLAUDE.md: "`docs/spec-corrections.md` wins over the spec body … **do not silently pick a
   reading**". The amendment does not pick silently: it flags the reading (`PREREG:965-972`). But it
   adopts the reading by default, and it asserts "This is not a new spec/corrections conflict",
   which is itself a reading.
2. **It moves run 1 away from the regime its planned successors use.** D2(b) keeps "'Training
   continues' … as a later arm, pre-registered before it runs". Spec E1/E3 train the transformer
   jointly. Both necessarily run the training forward in train mode, under correction 20's LM
   clause. A φ fitted on clean gestalts in run 1 therefore differs from those runs in mode as well
   as in freezing. Any run-1-to-successor comparison inherits that second difference.
3. **It changes the premise of a signed item.** L1(a) (signed: "a second `no_grad` eval-mode
   forward; its cost is measured in the PR") was chosen on the premise that the training forward is
   train-mode. ADR-0009 §1: "a capture taken from the training forward is train-mode … So the
   training loop needs an eval-mode source for `α`". Under C-1 that forward becomes numerically
   redundant (`PREREG:997`). This is not a contradiction, but it is a change to the setting a
   signed decision assumed.
4. **It reverses a reviewed build decision.** The build recorded and the earlier `feat/rsr-run1-ready`
   review accepted `frozen_model_mode = "train (dropout live)"` (m-4; `loop.py:1065-1068`). The
   owner's ruling text does not address mode either way.
5. **The memory regime differs from the substrate's training.** Arm B learned to *use* memory while
   writing train-mode gestalts. Under C-1, run 1's training-time memory is eval-mode throughout.
   The amendment's point 3 shows this matches how the substrate was *measured*, not how it was
   *trained*.

**MAJOR-A1-2. The oracle reference is coupled to O1, and is not an upper bound if O1 = 0.**

- `PREREG:1299` makes O1 set "also the oracle reference's construction".
- The original §7.2 (`PREREG:338-339`) used `OraclePolicy(discounted_demand(doc, γ_o))` with
  γ_o ∈ (0, 1). That is Belady's MIN, decision-identical for every such γ_o (T7, `PREREG:685-686`;
  `oracle.py` docstring).
- O1's option list includes γ = 0 (`PREREG:1311-1315`). At γ_o = 0,
  `OraclePolicy._future(sentence, step) = discounted_demand[step+1][sentence]` (`oracle.py`) sees
  only the very next step's demand. Every slot not queried at t+1 ties at 0, and the lowest index
  wins. That is a one-step-lookahead rule, not MIN.
- Oracle regret and the headroom share `(acc_arm − acc_fifo) / (acc_oracle − acc_fifo)` would then
  lose their meaning as an upper bound, and the denominator can approach 0.

*Fix:* decouple. Fix γ_o to any value in (0, 1); per T7 the decisions are identical. One example is
lookahead-room's `ORACLE_GAMMA = 0.97`. State that the oracle's γ is a construction parameter, not
O1.
