## (a) A3d.1 against `parse_owner_table` (`a811714`, `run.py:862-944`)

| A3d.1 rule | parser | match |

| heading is exactly one whole line, once in the file | `at = [i for i, x in enumerate(text.splitlines()) if x == heading]`; 0 gives `absent`, ≥2 gives `malformed` | ✓ |
| zero or more blank lines | `while … not lines[i].strip()`, so whitespace-only lines also count as blank | ✓ (slightly looser) |

**Reading the probes:**

- **Whitespace and lookalikes fail safe.** A trailing space, a curly apostrophe, NBSP, a
  zero-width space, a Cyrillic `О` or fullwidth digits all give `absent` or `malformed`, never a
  wrong `filled`. `[0-9]` in a Python `str` pattern is ASCII.
- **CRLF parses correctly**, because `splitlines` strips `\r`.
- **A second table** right after the first gives `malformed`. After a blank line it is ignored, and
  the first table's values are read, which is correct.
- **A fenced copy alongside the real heading** gives two occurrences, so `malformed`. That is safe.
- **A fenced copy *alone*** is read as the owner table, because the parser does not know about
  fences. This is MINOR-A3d-1.
- **`str.splitlines` also splits on ` `, ` `, `\x85`, `\x0b`, `\x0c` and `\x1c`–`\x1e`.**
  A source line containing one of these before the heading text becomes a "whole line" to the
  parser but not to a Markdown reader. This is exotic.
- **γ = 1 is accepted by the format.** It is refused downstream: `check_gamma_horizon` raises for
  γ ≥ 1 in `train()`, so every job exits rc 1 with no heartbeat, which is `did_not_run`. That is
  safe but late.

## (b) A3d.2: ordering and ties

**Against the rules.**

- `R-2026-09-22-inert-exit-5` gives inert 5, "a control fails → 3 DID_NOT_RUN", and
  inconclusive → `1 FAIL`.
- A3b.3's table holds both arm outcomes and control failures, and says `measure-seed` "takes the
  worst … using the A3b.5 order" (5 > 3 > 1 > 0).
- A3c.2 breaks arm ties in the order psiC, fifo, age.

A3d.2 makes explicit that the order spans arms **and** controls, and adds the exit-3 tie order:
arm outcomes, then C6 (`crashed`), then C1/C10, then C2–C4, C7, C8 (`did_not_run`). That is
consistent with all three, and **it closes my MINOR-A3c-1.**

**In the harness at `a811714`:**

- Arm outcomes go through `worst_outcome` (`run.py:1206-1214`: max rank, first in order) and return
  before any control is read.
- Then `cands` is built in the order C5-inert (5), C6 (3, `crashed`), C1/C10 (3, `did_not_run`),
  C5-inconclusive (1), and the worst is taken.
- C2–C4, C7 and C8 are applied at the end, giving `did_not_run`.

So the inconclusive-before-C6 problem I raised at `6267fd6` is fixed, and C6 beats C1/C10 on a tie,
as registered. The amendment still calls this TO-CONFIRM T18; it is already true at `a811714`.

**MINOR-A3d-2, wording.** In the harness, a C5 `inconclusive` or a C6 failure **stops the seed**
before C2–C4, C7 and C8 are computed. So A3d.2's sentence "if C5 reads `inconclusive` (exit 1) and
C6 or a control fails (exit 3), the seed exits 3" holds for C6, C1 and C10, but not for a C2–C4,
C7 or C8 failure that is never evaluated. The seed would exit 1 (`failed`). The run is unread
either way, so this is a precision gap, not a risk.

*Fix (either):* say "a control computed before the stop", or compute C2–C4, C7 and C8 before
stopping.

## Findings

None at BLOCKER or MAJOR.

**MINOR-A3d-1. Text that is not a real A4.1 table can still parse as `filled`.** This happens
when:

- the A4.1 heading line and its table appear only inside a fenced code block (an example quoted in
  Amendment 4 or later); or
- a Unicode line separator places the heading text on a parser-level "line" of its own.

C10 would still compare the parsed values with `launch-git.json` and the job records, so a fenced
example with **different** values fails C10. One whose values happen to equal the launch values
would pass.

*Fix (cheap, either or both):*

- register that the heading and table must not appear inside any fenced block, and that Amendment 4
  quotes no example copy;
- make the parser skip fenced regions and reject lines containing non-`\n` line separators.

**MINOR-A3d-2.** C2–C4, C7 and C8 are not evaluated after a stop, so the order is not total. See
§b.

**Nits:**

- the parser docstring's "without a pipe" is stricter than the code and A3d.1;
- blank-plus-malformed gives `malformed`;
- O1's format admits γ ≥ 1, which is refused later by the registry;
- T18 lists as TO-CONFIRM an ordering already implemented at `a811714`.
