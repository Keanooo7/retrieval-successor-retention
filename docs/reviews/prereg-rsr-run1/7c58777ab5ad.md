  vocabulary check across three shas.
- The three arms really are paired. The data order, dropout masks and warmup evictions are

**Five MAJOR findings must be fixed by a dated amendment before any run-1 step.**

1. The PREREG says LRU "is not implemented" (`PREREG:389`). It is implemented, and it has
   already been run.
2. The exit-code table is wrong. A warm-start refusal exits **1**, not 3. I measured this.

   it.

The run also cannot start until Brendan rules **O1 (γ)** and **O4 (φ weight decay)**. The PREREG
already gates on both. O2 and O3 are not owner-reserved, so they should not gate on Brendan

### B. Pairing

- **Data order.** `torch.randint(..., generator=gen)` uses `gen = torch.Generator(device).manual_seed(seed)`
  (`loop.py:919`, `:1200-1202`), the same in every arm. φ is drawn from its own CPU generator,
  `phi_generator` (`loop.py:652-663`). The age table is zero-initialised and draws no RNG
  (`value_head.py:199-210`).
- **Dropout masks.** All three arms draw dropout from the global stream in the same order. The
  RSR arms' extra eval forward is `model.eval()` under `no_grad` (`policy_loop.py:362-376`). The
  warmup diagnostics score under `no_grad` (`rsr.py:535-540`). `vacuity.py` uses no RNG
  (grepped). L_MC backward and `opt.step()` touch only φ.
- **Tests.** I ran six existing tests at `7c58777`. They exited with rc 0:
  `passed=6 failed=0 skipped=0 errors=0`. They were:
  - `test_the_eval_forward_draws_no_rng_and_restores_the_mode`;
  - `test_the_training_forward_is_unchanged_by_the_eval_forward`;
  - `test_fifo_and_rsr_arms_see_the_same_first_batch`;
  - `test_the_frozen_option_is_recorded_and_moves_no_transformer_weight`;
  - `test_a_frozen_fifo_arm_runs_without_an_optimizer`;
  - `test_warmup_evicts_fifo_and_phi_still_trains`.
- **Warmup.** `warm = t_warm > 0 and train_step < t_warm` (`rsr.py:530`). With `T_warm = 16.0`,
  steps 0–15 call `FIFOPolicy.select_eviction`, so the evictions are identical to the FIFO arm's.
- **ν.** ν = 0 in both RSR arms, and the age arm refuses ν ≠ 0 (`rsr.py:378-386`). There is
  no ν difference between arms.
- **`srep_norm_reg_weight`.** It is 0.01 in **all three** arms, so it is not an inter-arm
  confound. It differs only from the substrate's training value of 0.0. Under freeze,
  `objective = None` (`loop.py:1239`), so it moves no update. It enters `loss` and `loss_sum`
  only (`loop.py:1171`, `:1266`, `:1328`). It does not enter `loss_lm`, `loss_real_tokens`,
  `ppl` (`:1346`, which uses `loss_lm`) or liveness. `PREREG:250` handles this correctly.
- **Checkpoint cadence.** The cadence is identical across arms (`--ckpt-every 3000`), and the
  save happens after the last step. It is not a confound.
- **Optimizer.** The FIFO arm builds no optimizer. The RSR arms put the frozen model's params in
  AdamW groups with `grad=None`, so AdamW skips them, decay included (`loop.py:1019-1023`). That
  is consistent with C3.
- **C0.** C0 is **not** implied by the training commands (see MINOR-3). **C2 is implied by the
  code**: for k < 16 every arm runs an identical training forward on identical inputs, masks
  and memory at 1 thread. C2's batch check is weak, however (MINOR-4).

## MAJOR

**MAJOR-1. LRU is implemented, and the PREREG drops §7.1 item 3 on a false premise.**
`PREREG:389`: "LRU (§7.1 item 3): not run. It is not implemented. RESULTS says so."

- `src/rsr/baselines/lru.py` is a working 101-line `LRUPolicy`, keyed by `(row, written_at)`.
  It is device-tested (`tests/test_device_placement.py:220`).
- It was already run as an evaluation-only arm in the newcomer bake-off
  (`experiments/newcomer-bakeoff/run.py:43`, `:364-398`; PREREG table row "`lru` | (f) LRU").
- Spec §7.1 lists "RSR must beat LRU" as one of three tests. Spec §5.4 calls failing to beat
  LRU "§7.1 vacuity, stated behaviourally". The signed L6 makes the §7.1 diagnostics mandatory
  in every RESULTS.
- LRU needs no training, so it can run on EVAL beside oracle and random. It needs an
  observe-capable loop, because it reads `attn.alpha`.

*Fix:* append an amendment that adds LRU as an evaluation-only reference on EVAL, with the
contrasts psiC − LRU and age − LRU. Alternatively, state a true reason it cannot run. Either
way, the false sentence must not reach RESULTS.

**MAJOR-2. The exit-code semantics are wrong, and two launch defects would produce a spurious
"1".**

- `PREREG:172`, `:434` (C1), `:559-561` and `:480` say a `WarmStartRefused` is "exit 3". They
  map `1` to "inconclusive liveness".
- Measured (§D above): a refusal exits **1** with a traceback and writes no heartbeat. The same
  holds for every exception `train()` raises: the closure `ValueError`, an override
  `ValueError`, and a crash after `hb.crash(e); raise` (`loop.py:1379-1381`). `main()` does not
  catch them (`loop.py:1669-1692`), and `run_main` is `sys.exit(int(status(main())))`
  (`exit_codes.py:160-162`). Only argparse usage errors exit 3 (`exit_codes.ArgumentParser`).
- §9's snippet adds two more sources of rc 1 or 3:
  - `> runs/rsr-run1/psiC.log` is opened by zsh before the command runs. `runs/rsr-run1/` does
    not exist, so the first arm fails with rc 1 without running.
  - `SLOT` has no `--wait`. `scripts/orchestrator/slot.py:122` defaults it to `0.0`, so a busy
    lane refuses with 3 and writes no job record (`slot.py:18-24`).
- The three `rc=$?` assignments (`PREREG:467-474`) overwrite one variable.

*Fix:* append an amendment.

- Map `1` to "an uncaught exception OR inconclusive liveness". Disambiguate by the heartbeat
  footer `status`, or by its absence, and by the slot job record.
- Map `3` to "slot refused or usage error".
- Add `mkdir -p runs/rsr-run1`, a `--wait`, and `rc_psiC`, `rc_fifo` and `rc_age`.

**MAJOR-3. ψ̂-C is trained on train-mode slot gestalts and evaluated on eval-mode ones. This is
undeclared.**

- The frozen model stays in train mode during training (`PREREG:66`; `loop.py:1065-1068`).
- The memory is written from the training forward's `out.srep` (`policy_loop.py:514`, `:533`).
  That gestalt has passed through `SrepHead`'s 0.15 dropout (`model.py:445`, `:450`), the
  residual dropout and the attention dropout.
- So every `s_i` that ψ̂-C regresses on and decides on during training is a dropout-noised
  gestalt. Only `c_t` is eval-mode (L2).
- The primary held-out measurement runs the model in eval mode (`PREREG:308-314`), so the
  memory there holds clean gestalts.
- The age arm reads no gestalt and FIFO reads none either. **The shift therefore hits only
  psiC.** It enters psiC − fifo and psiC − age as something other than "the eviction rule".
- ADR-0009 L2's own argument ("noise in a policy-relevant direction") applies to `s_i` as much
  as to `c_t`. The ruling (D2(b)) freezes the update. It does not require train mode.

*Fix:* either declare this in §5, §7.1 and the "does not show" list, with a diagnostic, or
amend the design. One diagnostic would be ψ̂-C's EVAL score rank-agreement with a train-mode-
memory replay. A design amendment would be an eval-mode training forward for all arms. That
would also remove the second forward. **That is a design change and needs re-review.**

**MAJOR-4. Single-seed CIs need an explicit scope, and the multiplicity is unbounded.**

- `PREREG:301-304` and `:316-329` define per-document paired bootstrap CIs. The document is the
  right resampling unit for EVAL sampling noise. But the CI holds the trained φ fixed: one
  φ-init (`phi_seed 4778511090664290076`), one data order, one dropout realization, one
  substrate seed.
- Measured precedent: B2's psiU-vs-ref Δ was −0.0784 [−0.0847, −0.0716] on seed 0 and −0.0202
  [−0.0254, −0.0147] on seed 2 (verified results row 6). The within-seed CIs are several times
  narrower than the between-seed spread, and they exclude each other.
- The only place the PREREG says this is the O2 table (`PREREG:594`). §7's reading rule and
  §14b.7's "does not show" list omit it.
- §7.1 alone is 3 contrasts × (5 accuracy buckets + 2 losses) = 21 CIs. §7.2 adds R, regret and
  headroom per arm. No single headline contrast is designated, so "CI above 0" on any one of
  them invites selective reading.

*Fix:* append three things.

1. A mandatory RESULTS sentence: every CI is conditional on this one trained φ and substrate
   seed, and does not estimate run-to-run variance.
2. One designated headline contrast. psiC − fifo, all-query accuracy, is the natural one.
3. A note that the remaining CIs are unadjusted for multiplicity.

**MAJOR-5. The launch does not pin a clean commit, and the code tree was being mutated during
this review.**

- `feat/rsr-run1-ready` has no commit after `211d6da`. Its worktree, however, held an
  uncommitted, changing edit to `src/rsr/train/loop.py`. At 02:46 PDT it was
  `if False:  # MUTATED` in place of `if (a.pool_offset is None) != (a.pool_length is None):`
  at `:1549`. The mtime moved again at 02:58. Someone was running mutation proofs in the very
  tree whose code run 1 would use.
- `_sha()` (`loop.py:81-95`) records `git rev-parse HEAD` only, with no dirty flag. A run
  launched from a dirty tree would therefore stamp a clean-looking sha.
- The slot wrapper already has the guard: `--pinned-sha` refuses on a HEAD mismatch or on
  changes outside `runs/` (`slot.py:84-101`). `PREREG:463` does not use it.

*Fix:* append an amendment.

- Run from a dedicated worktree at the final reviewed commit.
- Add `--pinned-sha <that sha>` to `SLOT`.
- Record `git status --porcelain` in RESULTS.

## MINOR

1. **The B2 numbers are misattributed.** `PREREG:420-421` calls Δ +0.0035 / +0.0082 / +0.0071
   "B2's ψ̂-C … (verified results row 20)". Row 20 is the newcomer bake-off's per-arm outcome
   on `EVAL_NB`. B2's own ψ̂-C Δ are row 7: +0.0063 / +0.0085 / +0.0094. The expectation's
   logic is unchanged.
2. **One of the three reasons for 3000 steps is wrong** (`PREREG:281`). "It is arm B's own
   training length" does not hold: arm B is 1000 memorisation steps on `[0, 64)` plus 2000
   stream steps (§A). A φ-only run from a warm start is a different regime. The step count is a
   values call, not derivable (see *Owner items*, R-1). There is also an internal tension.
   Reason 2 says φ needs O(10³) steps to fit, yet handover happens at k = 16. So for an early
   stretch the scored rule runs on a near-untrained bilinear head. That makes evictions
   near-random under the censored target. The §7.3 500-step blocks should report this
   explicitly, for example as the first block's displacement distribution beside random's.
3. **C0's placement contradicts §9.** `PREREG:135-136` says `run.py` re-asserts disjointness
   "before any model is loaded". But §9 launches training with `python -m rsr.train.loop`
   directly, and `run.py` is measurement-only (`PREREG:482`). `train()` checks closure
   (`loop.py:1111`) but not disjointness. Either add a pre-launch C0 step to §9 or reword C0.
   The ranges are verified (§A), so the risk is low.
4. **C2's batch check is vacuous as written.** `n_targets_scored` is `valid.numel()` summed over
   steps (`loop.py:1182`). That is `16 × 63 × 48` every step, whatever the batch. Use
   `n_pad_targets_scored` or `pad_target_fraction` together with `n_answer_targets` as the batch
   fingerprint. Both depend only on the drawn documents. Better still, log a hash of `sel`.
5. **The commands are sequential but §10 describes them as concurrent.** The §9 zsh lines run
   one after another, giving about 2.2 + 1.3 + 2.2 h. `PREREG:520` assumes concurrency.
6. **The heartbeat attribution claim is overstated** (`PREREG:392-393`, `:639-643`). The defect
   is confirmed: `RSRPolicy` and `FIFOPolicy` both lack `attribution()`, so `attr` is always
   `None`. "Run 1 is covered" overstates it. With `b` off and ν = 0, §3.4's decomposition has a
   single term and is vacuous rather than covered. RESEARCH-CONTEXT §10.4 already records the
   field as a config echo ("NOT IMPLEMENTED"). Say so.
7. **"One pass" is not literal.** With-replacement sampling (`PREREG:142-144`) means T_warm's
   one "epoch" draws 256 documents but sees about 162 distinct ones (256·(1−(1−1/256)^256) =
   162.0). The ruling's text reads "One pass over the document pool: 256 documents seen". The
   PREREG declares its reading (good). Whether that reading is the ruling's is the owner's call;
   see R-2.
8. **The branch search was described inaccurately.** `PREREG:134-135` says the only hits were
   float digits. There is also the unit-test range `(999000, 1001048)` in
   `tests/test_newcomer_bakeoff.py`. It is harmless and touches no document.
9. **There are no intermediate φ snapshots.** `--ckpt-every 3000` was chosen against record
   pickling. Measured (§E), pickling 1.5M records costs about 6 s and about 105 MB, so
   checkpoints at 1000 and 2000 are affordable. They would let the §7.1 harness show whether
   φ's held-out behaviour had settled. This is optional.
10. **The expectations must not become a scorecard.** `PREREG:408-427` gives numeric ranges.
    That is fine as labelled. §14b.8 should say that expectation-vs-outcome is reported as text,
    never as "met" or "missed".
