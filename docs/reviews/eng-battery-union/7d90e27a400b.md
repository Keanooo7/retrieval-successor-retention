## MINOR-1: deleting a constant is not handled by the one-sided rule (the docstring says it is)

`battery_union.py:172-181` only iterates over theirs' constants:

- **C1.** Ours deleted a constant and theirs kept it unchanged. It is re-added as
  "new in theirs" (probe: `RESURRECTED new_consts=['_REVIEW_GATE_COUPLING']`).
- **C2.** Theirs deleted a constant and ours kept it. The deletion is silently dropped.

Entries in the same situation are refused. The docstring at `:30` claims "the same
one-sided rule" for constants. The impact is low, because an orphan `_X_COUPLING`
tuple is inert.

**Fix:** mirror the entry logic.

- If `ov is None and bv is not None`, refuse ("ours deleted").
- Loop over `b.const_order` and refuse where theirs deleted a constant that ours kept.

## MINOR-2: a malformed entry crashes the tool instead of refusing, and nothing checks that the output parses

At `battery_union.py:108`, `while lines[j] != "    ),\n": j += 1` has no bound. A
last entry without its `    ),` raises `IndexError` (probe X-last:
`CRASH IndexError list index out of range`). The crash writes nothing, so it is not
unsafe, but it is not the documented exit 3.

A missing terminator mid-body swallows the next entry. That case is refused, but the
reason given is misleading: "ours deleted it" (probe X-mid).

**Fix:**

- Bound the loop and raise `Refused`.
- Before writing, `ast.parse(res.text)` and check that
  `len(split(res.text).entries) == len(o.entries) + len(added)`.

## MINOR-3: the git path is hard-coded, so the new tests error on the Linux CI runner

`battery_union.py:60` sets `GIT = "/opt/homebrew/bin/git"` with no fallback. Some
tests depend on it:

- `tests/test_battery_union.py:164-176` and `:214-219` use `bu.GIT`;
- the CLI and real-merge tests use it through the script.

`.github/workflows/ci.yml` runs on `ubuntu-latest`. There, the `repo` fixture and
`_have()` raise `FileNotFoundError`, so four tests ERROR instead of skipping.

Precedent exists: `scripts/orchestrator/hooks.py:124` does the same. Most of the tree
uses `shutil.which("git")` instead (`loopcore.py:84`, `workqueue.py:136`). CI is
currently red for an unrelated reason (a `ruff format` failure in
`scripts/battery_subset.py`), which masks this.

**Fix:** `GIT = "/opt/homebrew/bin/git" if Path(...).exists() else shutil.which("git")`.
