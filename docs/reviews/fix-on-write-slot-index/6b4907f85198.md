## What was checked, and held

- **`newcomer_slot` equals `write_at`'s own rule.** Compare `policy_loop.py:68-81`
  with the replaced line `slot = torch.where(full, m-1, k)`: `full` is `k >= m` at
  `:99`, so the two are identical. `write_at` now calls it (`:117`), and the loop
  calls it on the **pre-write** mask (`:388`). Randomised property probe over 300
  trials:
  - batch 1-5, `M` 1-6, a random write mask and random victims;
  - 4612 write events, 0 bad;
  - `mem.step[r, landed] == t`, the slot is valid, `kv[r, landed] == srep[r]`,
    `written_at` is unique among live slots, and `valid` stays a prefix.
- **`written_at` really is unique per row.** `run_policy_loop` initialises memory
  fresh on each call (`:333`), `t` is strictly increasing, and a row writes at most
  once per step. Invalid slots carry step `-1` (`model.py:92`) and are excluded by
  `live`.
- **LRU.** It is keyed by `(row, written_at)` (`lru.py:66-98`). Probe results:
  - row 0 attending its slot 0 does not protect row 1's slot 0 (victims 1 and 0, as
    expected);
  - after a mid-memory eviction the record follows the occupant (`written_at`
    `[0, 2, 3, 11]`, next victim index 1, which is `written_at` 2);
  - pruning in `on_write` keeps each row's dict bounded by `M`.
- **E0b.** `newcomer_slot` and the `RuntimeError` guard (`:393-398`) consume no RNG
  and do not touch the FIFO path's tensors. `tests/test_reduction.py` gives
  20 passed, 0 skipped.
- **Other policies.** I grepped every `def on_write` in `src/` and `experiments/`:
  - FIFO, random, oracle, RSR (`rsr.py:485`), and the policies in `b0-ceilings`,
    `retention-readability` and `lookahead-room:301-378` are no-ops or ignore `slot`;
  - `e0e/run.py:227` and `lookahead-room/run.py:537` key by `step` or `written_at`,
    not by `slot`;
  - H2O, leading_edge and expire_span are `NotImplementedError` stubs.

  None changes behaviour.
- **The battery anchors.** `--check-anchors` gives `252/252 anchors occur exactly

## MINOR-1: the two unit-test harnesses still drive `on_write` with the old contract

The protocol docstring now guarantees `slots.written_at[slot] == step` on every
`on_write` call (`policy.py:259-266`). Two harnesses break that guarantee:

- `tests/test_reduction.py:92-102` (`_run`)
- `tests/test_policies.py:~100-112` (the drive helper)

Both still call `policy.on_write(s, v, step)`, where `s` is the **pre-write** state
and `v` is the victim, in an in-place replacement memory with no compaction. Under
the new LRU `on_write` (`lru.py:94-98`), that seeds a record for the **evictee's**
`written_at`. The newcomer's record is not seeded. This is harmless for LRU, which
falls back to `max(written_at, ...)` and prunes the stale record on the next write,
so every test still passes. But these harnesses exercise a protocol the loop no
longer implements. A future stateful policy (H2O) tested through them would be
tested against the wrong contract.

**Fix:**

- Build the post-write state (`written[v] = step`, then `_state(...)`) before calling
  `on_write`.
- Add an `assert s.written_at[v] == step` in each helper.

## MINOR-2: `headroom.simulate` never calls `on_write` or `observe` (pre-existing; the author flagged it)

`src/rsr/metrics/headroom.py:50-58` calls only `select_eviction` and `write_at`. The
new `MemoryState.row` docstring (`policy.py:76-84`) names `headroom.simulate` as a
legitimate single-row caller of the protocol. A stateful policy (LRU, and H2O later)
run through it silently loses all cross-step state.

The branch does not introduce this. I record it because the docstring now points
readers at it.

**Fix:** call `policy.on_write(memory_state(mem, t, 0), int(newcomer_slot(mem_pre.valid)[0]), t)`
after `write_at` in `simulate`, or have `simulate` refuse a policy with state.

## MINOR-3: integration note, expire_span's docstring goes stale

The author notes that `feat/expire-span`'s sentence "run_policy_loop passes on_write
the victim index" becomes false once this branch merges. Whichever branch merges
second must fix that sentence.
