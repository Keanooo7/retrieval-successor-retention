## (1) Is every finite row identical to `a992d7c`?

Yes, in both the forward and the backward pass.

**The argument:**
- `where(c, x, y)` with `c = total > 0` and `where(c', y, x)` with `c' = total == 0` pick the same
  branch whenever `c' = ¬c`.
- For finite totals, `¬(total > 0)` and `total == 0` differ only when `total < 0`. A negative
  total cannot occur: `att` is a softmax output, so it is `≥ 0`, and
  `weight = clamp(·, 0, 1) · live · keep` is `≥ +0`.
- A total of `-0` gives the same choice under both guards: `-0 == 0` is true and `-0 > 0` is false.
- `where`'s backward sends the gradient to whichever branch it selected, so when the selection is
  the same, the gradients are the same.
- The two guards therefore differ only on a NaN total, which is the intended change.

**The measurement** compares the `a992d7c` expression with `b49694a`'s `_reweight_attention`, bit
for bit, through an `int32`/`int16` view. The upstream gradient is ×10.

| case | forward | `att.grad` | `w.grad` |
|---|---|---|---|
| ordinary rows | identical | identical | identical |
| a batch mixing an empty row, partially weighted rows and fully weighted rows | identical | identical | identical |
| subnormal total (`0 < total < tiny`) | identical | identical | identical |
| all-`-0` weights | identical | identical | identical |
| bf16 attention | identical | identical | identical |
