## 1. Headline, for the cognitive reader

**The working memory is live once the objective is repaired, but it does not yet help the model answer.** On the new rewardable corpus, with the masked objective (arms B and C of `decisive-shuffle`), handing a row another document's memory moves the model's predictions far more than it moves an untrained model's. So memory is read and carries row-specific content. With the old objective (arm A), the memory collapsed to near-identical contents in every row, which is what the old "inert" result (#17 / §10.3) was actually seeing. By §10.3's own rule this is the **"live on some arm"** outcome, and it licenses the per-run liveness wiring brief (written, not started). It does **not** show retrieval: answer-token loss with the model's own memory stays at or above chance (ln 16) in every arm and every gap bucket.

**Nothing tonight bears on whether RSR discovers Kintsch & van Dijk's leading-edge strategy.** Tonight established the precondition for asking that question: that TG has a working memory a retention policy could act on. Before tonight, a null on E1/E3/E7 would have been uninterpretable; it no longer is. But until the memory *helps* on answer tokens, no eviction rule has anything to win.

### The decisive run (`decisive-shuffle`)
- **Question:** is TG's memory inert on a corpus whose objective requires retrieval?
- **Method:** #17's harness, reused. #17's Amendment 1 rule, unchanged: `ratio` = mean |per-token Δ| of the trained model over that of an untrained decoy at the same seed. The pre-registration was committed before S0-03 was spawned; its one amendment changes only how the secondary readout is scored.
- **Controls:** memory-disabled, own-memory and random-with-self all read exactly `0.0` on all nine (arm, seed) pairs.
- **Primary** `ratio` (mean ± sd):
  - A: `armA.ratio` 0.0030 ± 0.0023 → **inert**
  - B: `armB.ratio` 9.33 ± 4.68 → **live**
  - C: `armC.ratio` 7.74 ± 6.06 → **live**
- **Discriminators:**
  - Arm A's memory is near-identical across rows: `armA.train.cosine_trained` 0.9995, against the decoy's `armA.train.cosine_decoy` 0.565.
  - Replacing it with matched-norm noise still moves the loss: `armA.train.random_ratio` 2.10 ± 1.11.
  - So under the old objective the readout **uses** memory, but the memory carries no row-specific content. That is #17's second rival hypothesis, and it re-reads #17's null.
  - In B and C the trained memories are *less* collinear than the decoy's (`armB.train.cosine_trained` 0.483).
- **Answer tokens (held-out):**
  - Honest-memory answer NLL is `armB.heldout.answer.answer_all.honest_nll` 2.904 and `armC.heldout.answer.answer_all.honest_nll` 2.852: at or above ln 16.
  - Swapping memory moves answers hard (`armB.heldout.answer.answer_all.ratio` 25.99), but not toward the right answer.
- **Mutations:**
  - An arm swap is refused by the manifest-hash check.
  - A decoy aliased to the trained checkpoint gives `ratio == 1` → `inconclusive`.
  - Both redden named tests in `tests/test_decisive_shuffle.py`.
- **Does not establish:** retrieval; which of B or C is better (3 seeds cannot separate them, and the hinge stays the owner's decision); or behaviour past 300 iterations.
