## 3. Measures

**Unit: a cell** `(document, step t, rank i)`, with slot `i` occupied at step `t`, sentence `t` having
at least one real target, under FIFO. Batches are 16 consecutive ids of `D_E0d` in id order, so
resample donors come from the same 16 documents. That makes 64 batches per seed.

- **LOO Δloss** = `loo_delta_loss(model, docs, ids, mask, mode, seed=s)["delta"]`: the change in
  sentence `t`'s mean real-target NLL when slot `i` alone is knocked out, as a single-step
  intervention (the memory at `t+1` is the live one).
  - **Primary knockout: `resample`.** The slot's content becomes a same-kind gestalt from a different
    document at the same rank and the same step. It never has the displaced sentence's fact key. It
    stays in distribution.
  - **Secondary knockout: `zero`.** Out of distribution (the key becomes position-only), so it is
    labelled.
- **`r_i(t)`** = `retrieval_demand(trace, n_live, capacity=M, gated=...)`, read from the **same
  forward** that reads sentence `t` over the memory LOO knocks out. It is captured in eval mode.
  - **Primary: gated.** Correction 17 is the decided form.
  - **Secondary: ungated.** Correction 17's "raw" (`gated=False`).
  - The pre-share contribution magnitude `Σ_i contribution_i` is also recorded, per step, for §5.

### 3.1 Statistics, per seed (every one reported for gated × ungated × resample × zero)

1. **ρ_pool (primary): Spearman ρ over all full-memory cells** (`|memory_t| = M`, i.e. `t ≥ M`).
   Ties get average ranks.
2. **ρ_rank (required, decision-bearing): within write-order rank strata.** At full memory under
   FIFO, rank `i` fixes the slot's age exactly. So for each rank `i ∈ [0, M)`, compute Spearman ρ
   across that rank's cells. ρ_rank is the cell-count-weighted mean of the `M` per-rank values. Each
   per-rank ρ is also reported. This removes the recency channel: `ψ̂` may not see age (CLAUDE.md), so
   a target that agrees with LOO only through age is no use to an age-blind head.
3. **ρ_step (secondary, eviction-relevant):** the mean over full-memory steps of the within-step
   Spearman across the `M` live slots. Also reported: **bottom-1 agreement**, the fraction of
   full-memory steps where `argmin r_i` = `argmin Δloss`, against chance `1/M`.
4. **All-steps variants** of ρ_pool, including underfull steps (`t < M`), as a secondary. The rescale
   is known to bias stream-initial slots downward (D-7), so they are not in the primary.
5. **Per-layer profile, once, before collapsing** (correction 18): ρ_pool of each cross-attention
   layer's contribution (`contribution_per_layer`) against LOO Δloss, gated and ungated, with one
   entry per cross-attention layer of the checkpoint.
6. **By content kind (descriptive):** ρ_pool restricted to cells whose slot holds a pending assert,
   a spent assert, a query, or filler. This connects to the lookahead-room finding (RESEARCH-CONTEXT
   §9, finding 1).
7. **Flatness diagnostics** (§5): `q90|Δ|` for both knockouts, the median within-step CV of `r_i`, and
   the pre-share magnitude.

**Intervals.** A per-document cluster bootstrap: 2000 resamples of the 1024 documents, generator seed
`20260927`, 95% percentile. The same resample indices are used for every statistic of a seed. **Always
report the spread across the 3 seeds as well as the per-seed values. A seed-to-seed sd of exactly 0
is a broken result, not a clean one.**

**Not measured here.** §3.4's `ν · max cos` redundancy term (spec `:290`, "report ρ(score, LOO
Δloss) with and without it"). T3 fixes ν = 0, and RESEARCH-CONTEXT §10.4 settled that ν cannot
arbitrate within a near-copy pair. If E0d reads CONFOUND, the redundancy response is a separate,
later proposal.

## 4. The threshold (PROPOSED)

**`RHO_STAR = 0.5`**, applied to the gated `r_i` against resample LOO, per seed, through the 95% CI
(not the point estimate).

**Rationale.**

1. **What the number is for.** `ψ̂` is fitted to `r_i`, and eviction takes the argmin of `ψ̂`. If
   `r_i`'s ranking shares less than about a quarter of its rank variance with the causal ranking
   (ρ² < 0.25), then even a `ψ̂` that fits `r_i` perfectly ranks slots mostly by something other than
   their causal value. At that point "`r_i` is a confound" is the accurate description.
2. **Convention.** 0.5 is the conventional lower edge of a "large" correlation (Cohen's bands for
   `r`, commonly applied to ρ). "High ρ" should not be read as anything weaker than that. This is a
   convention, not a derivation, and it is stated as one.
3. **An asymmetric reading, so a noisy seed cannot produce a kill.** AGREE needs the CI lower bound
   ≥ 0.5. DISAGREE needs the CI upper bound < 0.5. A CI that straddles 0.5 is UNRESOLVED, never a
   kill.
4. **The stratified statistic has the same bar.** Agreement that disappears inside rank strata is
   agreement through age, which `ψ̂` is barred from using. So it cannot pass (the AGREE_VIA_RANK
   label).
5. **Disclosure.** The author of this threshold has read RESEARCH-CONTEXT §9 finding 1: in
   hindsight, FIFO-world immediate demand, pending facts ≈ 0.07 against filler ≈ 0.06
   (`runs/lookahead-room-r2/ledger.json`). That is prior evidence that `r_i` separates slot classes
   weakly. The threshold was not chosen to land on either side of any number from that ledger; it
   comes from rationale items 1–2.
6. **Sensitivity (descriptive only).** The per-seed labels are also reported at ρ* ∈ {0.3, 0.7}.
   They change no classification. If Brendan ratifies a value other than 0.5, it replaces 0.5 in a
   commit ordered before the run.

## 5. DEGENERATE / UNINFORMATIVE: when both sides are ≈ 0

RESEARCH-CONTEXT §10.4 records the case §3.2.1 is silent on: LOO |Δ| ~1e-7 nats and a
proxy-vs-LOO sign agreement of 0.510. The ρ there was uninformative because the model was
degenerate, not because the target was unfaithful. "About zero" is defined numerically, per seed, on
full-memory cells:

- **LOO flat:** `q90(|Δ_resample|) < 1e-3 nats`. A single answer token's retrieval effect is order
  0.1 nats. Spread over a sentence of about 6 targets, that is order 1e-2 nats per sentence, so
  1e-3 sits an order of magnitude below a real effect and four orders above §10.4's degenerate 1e-7.
- **`r_i` flat:** the median over full-memory steps of the within-step coefficient of variation
  (sd/mean over the `M` live slots) of gated `r_i` is `< 0.05`. That means every slot's share is
  within about ±5% of uniform, so `r_i` cannot rank. The pre-share magnitude is reported alongside.
  It is not a criterion, because a share cannot be zero.
- **DEGENERATE:** both flat. **LOO_UNINFORMATIVE:** LOO flat, `r_i` not flat. The truth has no
  signal, so no ρ is read. If `r_i` is flat and LOO is not, ρ is read normally but flagged
  `R_FLAT`.

### A1.1 Strata, statistics and a positive control (answers E0d-B1, BLOCKER)

**Why.** Only query sentences depend on memory in S0-03 documents. The review counts, on the
already-seen set E `[64, 1088)` with S = 48 and M = 16, query steps at 42.0–42.3 % of full-memory
steps, and query steps whose assert is still resident under FIFO at 1.93–1.95 % of full-memory
cells. At the remaining steps Δ is structurally ≈ 0 for every slot while `r_i` still sums to 1,
so the committed ρ_pool, ρ_rank and ρ_step are pulled toward 0 whatever `r_i`'s quality where it
matters, and CONFOUND is close to built in.

**§3.1 items 1–4 are replaced by the following.** Items 5–7 (per-layer profile, by content kind,
flatness diagnostics) are unchanged and remain descriptive.

> **§3.1 Strata (fixed by document structure before any data; never by Δ).**
> - **Q-steps:** full-memory steps `t ≥ M` whose sentence `t` is a query.
> - **A-cells:** at Q-steps, the slot holding the queried assert, when it is resident.
> - **N-steps:** every other full-memory step.
>
> **Statistics.**
> 1. **ρ_Q (primary):** Spearman ρ over all cells of Q-steps.
> 2. **ρ_Q,rank (decision-bearing):** the cell-count-weighted mean, over ranks, of the within-rank
>    Spearman ρ on Q-step cells.
> 3. **Secondary, reported and never decision-bearing:**
>    - ρ over all full-memory cells (the former ρ_pool);
>    - ρ over N-step cells;
>    - ρ_step and bottom-1 agreement on Q-steps;
>    - the fraction of `r_i` mass on N-steps.

The strata are read from the generator's sentence kinds and `doc.pairs` (`synthetic.py`), never
from Δ or `r_i`. The bootstrap of §3.1 ("Intervals") applies unchanged to every statistic here.

**Control C10 (added to §6).**

### A1.3 The bos-copy path (answers E0d-M2, MAJOR)

**Why.** `loo_delta_loss` leaves `bos_ctx = out.srep` of step `t−1` in place (`loo.py`, the FIFO

survives its own knockout through token 0. `loo.py`'s own docstring ("The bos-copy path at gap 1")

`loo_delta_loss` has no bos-off twin.

**Added to §3.1 and §8:**

> **Bos-copy sensitivity.** Every decision-bearing statistic is recomputed with rank M−1 excluded
> and with gap-1 Q-steps excluded. If the §8 class changes, the report says **BOS_SENSITIVE** and
> names both classes; the exit code follows the class with the exclusions. (A bos-off LOO variant,
> which passes `bos_valid = False` to both the live and the knockout forward, is a harness change
> that does not touch the forward pass. It may replace the exclusion if it is built and tested
> before the run.)

*Author's note (interpretation of "and").* I read "with rank M−1 excluded and with gap-1 Q-steps
excluded" as **one** recomputation with both exclusions applied together: every cell at rank M−1
is dropped, and every cell of a Q-step whose query has gap 1 is dropped. At a gap-1 Q-step the
A-cell is the newest slot, so the first exclusion already removes it; the second removes the rest

also judged on the excluded population. If the bos-off variant replaces the exclusions, the
decision to use it is committed before the run, in its own commit, with its test.

### A1.4 A crash does not share exit 1 with "kill fired" (answers E0d-M3, MAJOR)

**Why.** `exit_codes.run_main` is `sys.exit(int(status(main())))` with no `except`
(`src/rsr/exit_codes.py`), so an uncaught raise exits **1**, which in E0d means CONFOUND. The
module's own docstring records this collapse ("seven `experiments/e0*/run.py` stubs raised an
uncaught `NotImplementedError`, which Python reports as **1** -- *did not run* collapsing to *real
failure*"). The repo's convention is `3 = DID_NOT_RUN` ("environment / not implemented /
precondition refused").

**§8 "Exit semantics" is extended with:**

> The runner wraps the whole measurement in `try/except BaseException` and maps any exception to
> exit **3**, with the traceback in the ledger. Exit **1** is emitted only after the ledger key
> `e0d.class ∈ {CONFOUND, CONFOUND_INVERTED}` has been written. The verifier checks that rc and
> `e0d.class` agree.

`CONFOUND_INVERTED` is §8 row 3's class ("CONFOUND, INVERTED"); `CONFOUND` is row 4's. Every
other class's ledger value is written before its exit too, and the verifier's check covers every
rc (0 ↔ AGREE; 2 ↔ DEGENERATE / UNINFORMATIVE, AGREE_VIA_RANK / RECENCY_ONLY, MIXED / UNRESOLVED;
3 ↔ inconclusive).

*Author's note (`SystemExit`).* `except BaseException` also catches `SystemExit`, which is how
`rsr.exit_codes.refuse(code, reason)` exits with a *chosen* code from inside the call stack. A
`refuse(Exit.DID_NOT_RUN, ...)` maps to 3 either way. Any `SystemExit` raised before `e0d.class`
is written exits 3, whatever code it carries, so no path can emit 1 (or 0) without a written class.
This is how I read the review's rule ("any exception to exit 3"; "exit 1 is emitted only after
`e0d.class` has been written"); it does not relax it. `KeyboardInterrupt` maps to 3.
