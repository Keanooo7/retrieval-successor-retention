- **The PREREG's named risk is what happened: `survived` here means "not enough training", not "memory does not help".** The PREREG required the report to say so if `survived` came with near-chance live accuracy ("Author's expectation", last bullet). It did. In the `n4096` arm the model did not learn the answer task **even on its training documents**. `n4096.ckpt1000.train.live.gap_2_to_M.answer_nll` sits at `chance_ln16`, and so does `n4096.ckpt1000.heldout.live.gap_2_to_M.answer_nll`. The memorisation probe (`probe_documents` in the manifest) is inside every arm's training set. The same holds in the `n512` arm (`n512.ckpt1000.train.live.gap_2_to_M.answer_nll`). The training heartbeats of the `n512` and `n4096` arms (`runs/corpus-size-curve/n*/seed*/heartbeat.jsonl`, field `loss_answer_tokens`; not committed, `.gitignore` excludes them) show answer-token loss flat at about `chance_ln16` from early in training to the last step, on every seed of both arms. In the `n64` arm the same loss fell steeply. So at this run's training length a large corpus removed memorisation **and** removed any answer learning at all. The run cannot say whether memory would help in the `n4096` arm with more training. The verdict stands as preregistered.
- **The `n64` arm at `ckpt1000` shows B on every seed, reported and not read (PREREG).** `n64.ckpt1000.B` is true, and `n64.ckpt1000.heldout.slots_zeroed_minus_live.gap_2_to_M.answer_brier_over_16` exceeds `brier_margin` on every seed. But `n64.ckpt1000.heldout.live.gap_2_to_M.answer_brier_over_16` is **above** `brier16_uniform`: the live model is worse than the uniform forecast, and zeroing the memory makes it worse still. Brier is bounded, but it still charges overconfidence, so this confirms the memory carries answer information when the training set is memorised (`n64.ckpt1000.train.live.gap_2_to_M.answer_acc`). It does not show a well-calibrated benefit.
